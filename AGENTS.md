# AGENTS.md — Token Inspector Architecture Reference

Authoritative architecture reference for Claude Code, OpenCode, Gemini CLI, and any AI coding assistant working in this repository. Read this before touching any backend file.

---

## Project Purpose

Token Inspector is a standalone local service that centralises LLM token analytics across multiple projects. Any project that calls an LLM provider can push a structured event to this service after each call. The inspector stores the event, calculates its USD cost from a user-maintained pricing table, and exposes the aggregated data through a REST API consumed by a built-in vanilla JS dashboard.

**Design goals:**
- Near-zero always-on resource cost (single Python process, SQLite file, no Docker)
- Zero friction to connect a new project (one HTTP POST per LLM call, no auth, no registration)
- Cross-project visibility: compare token spend across models, roles, and projects in one place

---

## Architecture Overview

```
Connected Project
  └── push_token_event() ──POST /api/events──► Token Inspector (FastAPI, port 8100)
                                                   │
                                              SQLite DB
                                          token_inspector.db
                                                   │
                                         GET /api/analytics/*
                                                   │
                                          Browser Dashboard
                                       (vanilla JS + Chart.js)
```

**Single process, single file:** One `uvicorn` process serves both the REST API and static dashboard files. The SQLite database is a single file in the working directory.

**Cost at ingest:** USD cost is calculated when the event arrives, not at query time. This means changing a pricing rule does not retroactively update past events — only future events use the new price.

## Data Model

### `token_events` table

One row per LLM call pushed from a connected project.

| Column | Type | Nullable | Notes |
|---|---|---|---|
| `id` | TEXT PK | No | UUID v4, generated by inspector at ingest |
| `project_name` | TEXT | No | From `X-Project-Name` request header |
| `model` | TEXT | No | Must exactly match `pricing_rules.model` for cost calc |
| `role` | TEXT | Yes | Agent role string, e.g. `"backend_developer"` |
| `prompt_tokens` | INTEGER | No | Input token count. Defaults to 0 when caller provides `total_tokens` instead of a split count. |
| `completion_tokens` | INTEGER | No | Output token count. Defaults to 0 when caller provides `total_tokens` instead of a split count. |
| `cache_read_tokens` | INTEGER | No | Default 0; tokens served from prompt cache |
| `cache_creation_tokens` | INTEGER | No | Default 0; tokens written to cache |
| `process_time_ms` | INTEGER | Yes | Wall-clock LLM call latency in milliseconds |
| `request_size_bytes` | INTEGER | Yes | Raw prompt payload size in bytes |
| `response_size_bytes` | INTEGER | Yes | Raw response payload size in bytes |
| `estimated_cost_usd` | REAL | Yes | Null if no pricing rule found at ingest time |
| `status` | TEXT | No | `"success"` / `"error"` / `"timeout"`. Default `"success"` |
| `error_message` | TEXT | Yes | Non-null only when status is `"error"` |
| `complexity` | INTEGER | Yes | 1–5 complexity tier. Set by source project (e.g. myprojectteam planner) or async AI scorer when `prompt_text` is provided. Null until scored. |
| `prompt_text` | TEXT | Yes | Truncated to 3000 chars at ingest. Used only for async AI complexity scoring. |
| `recorded_at` | TEXT | No | ISO8601 UTC timestamp (`YYYY-MM-DDTHH:MM:SS.ffffffZ`) |

**Indexes:** `project_name`, `model`, `recorded_at`, composite `(project_name, recorded_at)`

### `pricing_rules` table

One row per model. Primary key is the exact model string.

| Column | Type | Notes |
|---|---|---|
| `model` | TEXT PK | Exact string used in `token_events.model` |
| `input_price_per_1m` | REAL | USD per 1 million prompt tokens |
| `output_price_per_1m` | REAL | USD per 1 million completion tokens |
| `updated_at` | TEXT | ISO8601 UTC, updated on every upsert |

## Cost Calculation

Cost is calculated in `routes/events.py:_calc_cost()` at ingest time:

```python
cost = (prompt_tokens / 1_000_000 * rule.input_price_per_1m +
        completion_tokens / 1_000_000 * rule.output_price_per_1m)
```

If no `PricingRule` row exists for the event's `model`, cost is stored as `null`. Cache tokens are **not** included in the cost formula — only `prompt_tokens` and `completion_tokens` are billed at the standard rate. If cache pricing is needed in the future, add `cache_creation_tokens` and `cache_read_tokens` terms with their own multipliers from the pricing rule.

When a caller provides `total_tokens` instead of separate `prompt_tokens`/`completion_tokens` (both 0), cost is approximated as `(total_tokens / 1_000_000) * avg(input_rate, output_rate)`. This covers callers like myprojectteam whose `TokenResult` only carries a combined actual token count.

## API Endpoints

### Ingest

```
POST /api/events
Header: X-Project-Name: <project-name>   (required, no auth)
Content-Type: application/json

Request body:
{
  "model": "claude-sonnet-4-6",          // required
  "role": "backend_developer",           // optional, nullable
  "prompt_tokens": 1200,                 // optional, default 0
  "completion_tokens": 800,              // optional, default 0
  "total_tokens": 1800,                  // optional; replaces prompt+completion split when both are unavailable
  "cache_read_tokens": 400,              // optional, default 0
  "cache_creation_tokens": 0,           // optional, default 0
  "process_time_ms": 3200,              // optional, nullable
  "request_size_bytes": 4800,           // optional, nullable
  "response_size_bytes": 3200,          // optional, nullable
  "status": "success",                  // optional, default "success"
  "error_message": null,                // optional, nullable
  "complexity": 3,                      // optional; 1–5 if known by source project
  "prompt_text": "..."                  // optional; truncated to 3000 chars; triggers async AI scoring when complexity absent
}

Response 201:
{ "id": "<uuid>", "estimated_cost_usd": 0.0105 }
```

### Event Log

```
GET /api/events?project=&model=&status=&page=1&page_size=50

Response 200:
{ "items": [ <TokenEvent>, ... ], "total": 42, "page": 1, "page_size": 50 }
```

All query parameters are optional filters. Items are ordered by `recorded_at DESC`.

### Analytics

All analytics endpoints accept a `days` query parameter (default varies). They filter events where `recorded_at >= now - days`.

```
GET /api/analytics/summary?days=7
→ { total_events, total_prompt_tokens, total_completion_tokens,
    total_cost_usd, unique_projects, unique_models, avg_process_time_ms }

GET /api/analytics/by-project?days=30
→ [ { project_name, event_count, total_tokens, total_cost_usd, avg_process_time_ms }, ... ]
   Sorted by total_cost_usd DESC

GET /api/analytics/by-model?days=30
→ [ { model, event_count, avg_prompt_tokens, avg_completion_tokens,
      avg_process_time_ms, total_cost_usd, cost_per_1k_tokens }, ... ]
   Sorted by total_cost_usd DESC

GET /api/analytics/by-role?days=30
→ [ { role, event_count, total_tokens, total_cost_usd }, ... ]
   Sorted by total_cost_usd DESC. Events with null role are grouped under "unknown".

GET /api/analytics/timeseries?days=30&granularity=day&project=<optional>
→ [ { date, total_tokens, total_cost_usd, event_count }, ... ]
   Bucketed by YYYY-MM-DD, sorted chronologically. granularity param accepted but
   currently only "day" is implemented — finer granularity is a future extension.

GET /api/analytics/by-complexity?days=30&project=<optional>
→ [ { complexity, avg_cost_usd, avg_tokens, event_count }, ... ]
   Sorted by complexity ASC. Excludes events with null complexity.

GET /api/analytics/routing-recommendations?days=30&project=<optional>
→ [ { role, complexity, most_used_model, recommended_model, avg_cost_most_used,
      avg_cost_recommended, estimated_savings_pct, data_points }, ... ]
   Only emits suggestions when cheapest model ≠ most-used model AND savings ≥ 10%
   AND each (role, complexity, model) bucket has ≥ 3 data points. Sorted by
   estimated_savings_pct DESC.
```

### Pricing Settings

```
GET /api/settings/pricing
→ [ { model, input_price_per_1m, output_price_per_1m, updated_at }, ... ]
   Sorted by model ASC

POST /api/settings/pricing
Body: { model, input_price_per_1m, output_price_per_1m }
→ 200 { model, input_price_per_1m, output_price_per_1m }
   Upserts: creates if not exists, updates if exists.

DELETE /api/settings/pricing/{model}
→ 204 No Content
   model is URL-path-encoded. Uses {model:path} to handle slashes in model names
   like "openai/gpt-4o".
```

## Dashboard Architecture

The frontend is a single-page application served as static files from `static/`. FastAPI mounts the `static/` directory and serves `static/index.html` at `/`.

**View routing:** `app.js` manages four views by toggling CSS `hidden` class. No URL hash routing — navigation is in-memory only. Page reload always returns to Overview.

**Chart lifecycle:** Each chart is stored in the `charts` object keyed by name. Before creating a chart, `destroyChart(id)` is called to prevent Chart.js canvas reuse errors. This is critical — skipping destroy causes `Canvas is already in use` errors.

**Data flow:** Every view loads its data fresh on each navigation by calling the relevant API endpoints. There is no client-side cache — all state lives in the API response.

**Five views:**

| View | API calls | Charts |
|---|---|---|
| Overview | summary, by-project, by-model, timeseries | Line (tokens+cost), Bar (top 5 models by cost) |
| Projects | timeseries (per-project), by-role, by-model, events | Line (daily tokens), Donut (by role), Donut (by model) |
| Models | by-model | Horizontal bar (avg latency) |
| Complexity | by-complexity, routing-recommendations | Bar (avg cost by tier C1–C5), Routing recommendations table |
| Settings | settings/pricing | None — table with inline edit/delete form |

## Integration: Connecting a Project

Add this helper and call it after every LLM response. Errors are silently swallowed — the inspector being down must never fail the calling project.

```python
import httpx

async def push_token_event(
    model: str,
    role: str | None,
    prompt_tokens: int,
    completion_tokens: int,
    cache_read_tokens: int = 0,
    cache_creation_tokens: int = 0,
    process_time_ms: int | None = None,
    request_size_bytes: int | None = None,
    response_size_bytes: int | None = None,
    status: str = "success",
    error_message: str | None = None,
    project_name: str = "my-project",
):
    try:
        async with httpx.AsyncClient() as client:
            await client.post(
                "http://localhost:8100/api/events",
                headers={"X-Project-Name": project_name},
                json={
                    "model": model,
                    "role": role,
                    "prompt_tokens": prompt_tokens,
                    "completion_tokens": completion_tokens,
                    "cache_read_tokens": cache_read_tokens,
                    "cache_creation_tokens": cache_creation_tokens,
                    "process_time_ms": process_time_ms,
                    "request_size_bytes": request_size_bytes,
                    "response_size_bytes": resp_bytes,
                    "status": status,
                    "error_message": error_message,
                },
                timeout=2.0,
            )
    except Exception:
        pass
```

**myprojectteam integration point:** Call `push_token_event()` inside `_record_token_usage()` in `apps/dispatcher/app/dispatcher.py` immediately after the existing `TokenUsage` insert. The `TokenResult` from the provider already has `actual_tokens`, `cache_creation_tokens`, and `cache_read_tokens` — map them directly to the helper parameters.

## Architectural Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Database | SQLite | No server process, zero idle RAM, suitable for single-writer personal analytics tool |
| Auth | None — trust `X-Project-Name` header | Personal local tool; friction of keys outweighs security benefit |
| Cost timing | At ingest | Consistent: past events reflect prices at the time they were recorded |
| ORM | SQLModel (wraps SQLAlchemy + Pydantic) | Single model definition covers DB schema and API validation |
| Frontend | Vanilla JS + Chart.js | No build step, no Node.js dependency, minimum always-on overhead |
| Session type | `sqlmodel.ext.asyncio.session.AsyncSession` | Required for `.exec()` method; SQLAlchemy's `AsyncSession` lacks it |

## Known Gotchas

1. **SQLModel `AsyncSession` vs SQLAlchemy `AsyncSession`** — `sqlalchemy.ext.asyncio.AsyncSession` does not have `.exec()`. All files must import `from sqlmodel.ext.asyncio.session import AsyncSession`. Symptom: `AttributeError` at startup.

2. **Pricing rule changes are not retroactive** — cost is stored at ingest time. Updating a price via `POST /api/settings/pricing` only affects future events. Past events in `token_events.estimated_cost_usd` are frozen.

3. **Seeding only runs when table is empty** — `_seed_pricing()` checks `COUNT(*)`. If you add a new model to `SEED_PRICING` in `models.py`, it will not be auto-inserted into existing databases. Insert it manually with `POST /api/settings/pricing` or delete the DB file.

4. **`model` key must use exact provider prefix** — the model string in the event payload must exactly match the `pricing_rules.model` primary key (case-sensitive, no normalization). `claude-sonnet-4-6` ≠ `Claude-Sonnet-4-6` ≠ `claude-sonnet-4.6`.

5. **Chart.js canvas reuse crash** — navigating away from a view and back without calling `destroyChart()` first causes `Canvas is already in use. Chart with ID 'N' must be destroyed before the canvas can be reused`. Always call `destroyChart(id)` before `new Chart(...)` in `app.js`.

6. **`uvicorn` not on PATH on Windows** — use `python -m uvicorn` instead of bare `uvicorn`. The pip-installed executable may not be discovered by the shell.

7. **CWD-relative SQLite path** — the DB file is created relative to the working directory when uvicorn starts. Starting from the wrong directory creates a second DB file in an unexpected location with no pricing data.

8. **`timeseries` granularity param is a stub** — the `granularity` query parameter is accepted but only `"day"` bucketing is implemented. Finer granularity (hour, week) requires a `strftime` change in `analytics.py:timeseries`.

9. **`by-role` groups null roles as "unknown"** — events with no `role` field are counted under the `"unknown"` key in role analytics. This is intentional — it prevents null grouping bugs in the JS donut chart.

10. **`DELETE /api/settings/pricing/{model:path}` requires URL encoding** — model names containing slashes (e.g. `openai/gpt-4o`) must be percent-encoded in the DELETE URL: `DELETE /api/settings/pricing/openai%2Fgpt-4o`. The `{model:path}` FastAPI route parameter handles decoding server-side.

11. **`complexity_scorer.py` creates its own session** — the scorer is called as a FastAPI `BackgroundTask` after the request completes, so the request-scoped session is already closed. `score_complexity()` opens its own session via `AsyncSessionLocal`. Never pass a request-scoped session to a background task.

12. **`total_tokens` cost uses avg rate, not split rate** — when a caller sends `total_tokens` (with prompt_tokens=0, completion_tokens=0), the cost formula uses `avg(input_rate, output_rate)`. This is an approximation. For accurate cost, send separate `prompt_tokens` and `completion_tokens`.
