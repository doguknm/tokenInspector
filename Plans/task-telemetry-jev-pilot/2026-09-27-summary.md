TASK_SUMMARY:
The work has three parts.

1. **Hermes producer plugin (Faz 0).** Fix two defects:
   - response-metadata field mapping;
   - no durable disk spool for failed batches. The fix adds a dead-letter folder, fsync durability and producer-side scrubbing before spooling.

2. **tokenInspector backend (Faz 2).** Add additive schema and services:
   - `tasks`, `task_evaluations`, `evaluator_runs`, `evaluator_attempts`;
   - redacted per-task prompt storage with a 30-day retention. The retention covers the live DB, the WAL and DB-directory backups, and is enforced when prompts are read;
   - request-composition fields and task hierarchy status;
   - metadata-only task derivation from existing events;
   - a budget-safe JEV scoring worker: durable per-call reservations, typesafe-ai → digitalocean fallback, Retry-After honored exactly;
   - mandatory auth plus Host/Origin checks for the sensitive features;
   - a minimal API and a dashboard Tasks view.

3. **Pilot (Faz 3).** Hand-label about 50 **prospectively captured** tasks. Compare JEV scores against the human labels and against the existing request-shape-v1 heuristic, using a paired complete-case cohort.

Claude Code OTel/hook ingestion (Faz 1) is explicitly deferred. See OUT_OF_SCOPE.

ACCEPTANCE_CRITERIA:
Test owner in brackets. "tests-other(hermes)" = plugin tests run on hermes.

- **AC1:** The Hermes plugin maps the fields Hermes core actually emits (`assistant_content_chars`, `assistant_tool_call_count`, `assistant_message`/`response`) into `response_size_bytes`, `tool_call_count` and `role`. No response text is placed on the event. [tests-other(hermes)]
- **AC2:** No batch is silently dropped. Details:
  - A batch that fails to send is fsync-durably written to a disk spool and replayed on a later flush.
  - Permanently rejected (400/413/422) or corrupt spool files move to a bounded dead-letter folder and never block replay.
  - Prompt expiry in the spool, the dead-letter folder and orphan `.tmp` files is based on **capture time**. Expired prompts are stripped and the telemetry is kept (r2).
  - Task prompt text is scrubbed by the producer before it can reach the queue or the spool.
  - Drop, reject, dead-letter and expiry counters are visible (counters file + WARNING logs).
  - Loss of batches that exist only in memory is bounded and documented.

  [tests-other(hermes)]
- **AC3:** An additive migration adds `tasks`, `task_evaluations`, `evaluator_runs`, `evaluator_attempts`, `provider_cooldowns` and `retention_state` plus new nullable `token_events` columns. It runs in one explicit transaction on a dedicated migration engine, preceded by an **integrity-verified** online SQLite backup. Every pre-existing `token_events` column is unchanged row-by-row. The v9 application still starts and ingests against the v10 DB. An interrupted migration leaves schema v9 intact. [tests-other]
- **AC4:** Tasks are derived **metadata-only** from the existing `token_events` rows that carry `task_id`. Details:
  - Timestamps, request-shape-v1 start complexity and the completion signal are derived.
    - Start complexity uses one approved-provenance candidate rule shared by backfill and ingest, then deterministic time+event-id ordering (r2).
    - Completion is recomputed from timestamps per project+session, independent of arrival order (r2).
  - Hierarchy is `unknown` for historical rows.
  - Historical tasks have no prompt text, so they cannot enter the pilot. **Pilot tasks are collected prospectively**, after capture is activated.

  [tests-other]
- **AC5:** Per-task redacted prompt text (and human label notes) are retained at most 30 days from the **producer's capture time**, which is preserved across spool replays. Details:
  - Expired text is unreadable by the API, by pilot selection and by the JEV worker, even before the physical purge runs.
  - The purge nulls the text in the live DB, runs `secure_delete` and `wal_checkpoint(TRUNCATE)`, and re-purges and VACUUMs the DB-directory backups.
    - A busy checkpoint is persisted and retried even when no new rows expire (r2).
    - Retention stays scheduled whenever retained data exists, regardless of the capture flag. Interval 0 requires a verified all-copy purge (r2).
    - The lag target is one interval, not a guarantee. Failures are surfaced in a visible status.
  - A rollback runbook purges prompts with a standalone script.
  - Token/cost/difficulty metadata persist permanently.
  - Logical deletion versus physical erasure, and the limits on provider-side copies, are documented in ADR-002.

  [tests-other]
- **AC6:** The background JEV worker behaves as follows:
  - runs are reserved atomically (one active run, with a run id and queued/running/terminal state);
  - every HTTP call is preceded by a durable budget reservation with a conservative upper-bound token estimate, then reconciled to the gateway-reported cost;
  - it calls typesafe-ai first and falls back to digitalocean on 429;
  - it honors `Retry-After` exactly (seconds or HTTP-date) through **per-provider cooldowns persisted across tasks, runs and restarts**, and stops or defers the run when the wait exceeds the allowance (r2);
  - one per-provider attempt limit covers mixed 429/5xx;
  - responses are validated strictly (finite, bounded, exactly 5 levels, legend matching the rubric);
  - it silently skips when credentials are absent;
  - it never scores its own evaluator-usage call.

  [tests-other]
- **AC7:** A minimal API and a vanilla-JS/Chart.js Tasks view (no build step) list tasks with request-shape-v1 complexity, completion and hierarchy status, and, once scored, the JEV score, confidence and probabilities. Details:
  - stable ordering (`last_seen_at` desc, `task_ref` asc);
  - defined empty states;
  - stale-response protection;
  - a "showing latest 200" chart label when the cap is hit;
  - a real out-of-range page clamp;
  - Close invalidating in-flight detail responses;
  - chart-only failure handling;
  - a documented `children[]` shape;
  - a `projects` list that ignores the project filter (r2);
  - no prompt text in the UI;
  - HTML-escaped hostile strings.

  [tests-e2e, tests-other (Playwright stubs + API)]
- **AC8:** The pilot workflow does the following:
  - selects about 50 completed root tasks by stated stratified sampling;
  - records blind human difficulty labels (0–4 rubric) via a CLI that escapes terminal control characters. Labelling progress (labelled / skipped / not labelled) is persisted per labeler, and `score` takes an explicit `--labeler` (r2);
  - produces a comparison report (JEV vs human vs request-shape-v1) on a **paired complete-case cohort**, with at least 40 pairs required;
  - reports exclusions;
  - gives an explicit `INCONCLUSIVE — insufficient evidence` outcome when pairs are too few or statistics are undefined.

  [tests-other]
- **AC9 (new):** Request-composition counts are attributed to the correct categories: system, history, tool output, file content, file-ref count and tool names. They contain counts and names only, never content or paths. The backend validates and stores them. [tests-other(hermes) for attribution; tests-other for backend validation]
- **AC10 (new):** Task hierarchy works as follows:
  - Delegation/subagent children carry `parent_task_id`/`root_task_id`. The backend stores `hierarchy_status` = `root|child|unknown` and never downgrades `child`.
  - Unknown-hierarchy tasks are excluded from root-only sampling.
  - The plugin enables prompt capture only after the backend reports schema ≥ 10 and capture enabled (`GET /api/meta`).
  - The task terminal signal is: Hermes session end/finalize, or the next task start in the same session. Otherwise a task becomes `completion=inferred` after 60 minutes of inactivity. Completion is recomputed after late arrivals, including session-end markers without a `task_id` (r2).

  [tests-other, tests-other(hermes)]
- **AC11 (new):** When `STORE_TASK_PROMPTS=1` or `JEV_ENABLED=1`, `INGEST_TOKEN` is mandatory. Without it, those features refuse to start (ERROR log + `disabled_reason` in the status endpoints). Sensitive endpoints always require a configured token and reject a missing or wrong header. A Host allowlist and an Origin check protect against DNS-rebinding and cross-origin calls. The activation gate is also required. It has three phases: (a) approval + configuration preflight with the flags off (`config_errors == []`, `not_enabled` accepted), (b) controlled activation, and (c) post-start verification with no disabled reason (r2).
