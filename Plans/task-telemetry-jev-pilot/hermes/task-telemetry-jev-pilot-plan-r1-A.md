FINDINGS:
F1 [HIGH] backend.md Part B 0b–0c / §4 — Server-side scrubbing does not protect the producer spool — scenario: a prompt containing a free-text credential passes field-name redaction, delivery fails, and the credential is persisted in spool JSON before backend scrubbing — fix: apply the approved text scrubber before serialization/spooling, with producer privacy tests.
F2 [HIGH] backend.md §4 / summary privacy contract — The proposed scrubber does not enforce the explicitly prohibited content categories — scenario: a prompt includes `/srv/private/workspace`, an internal hostname, or a complete private Git remote; those survive the listed rules and reach JEV — fix: define and test coverage for prohibited categories; gate external evaluation on an approved residual-risk policy rather than treating “redacted” as sufficient.
F3 [HIGH] database.md secure_delete / backend.md §5 — The stated 30-day retention promise exceeds the deletion mechanism — scenario: an expired prompt remains in a backup or old WAL frames after a PASSIVE checkpoint; alternatively, disabling the loop leaves it indefinitely — fix: assign ownership for backup expiry and WAL sanitization, define maximum purge lag and failure alerts, and prevent indefinite retention when capture is enabled.
F4 [HIGH] backend.md §3, §6 / Part B 0b — Retention starts again at backend ingestion and expired text remains eligible until physical purge — scenario: an old spooled prompt receives a fresh retention period, or JEV reads text whose expiry passed between purge runs — fix: propagate a validated original capture timestamp, preserve its expiry across replay, and enforce expiry on prompt reads, selection and immediately before evaluator calls.
F5 [HIGH] backend.md Auth and Permissions — Sensitive access and charge-incurring operations fail open when INGEST_TOKEN is absent — scenario: capture/JEV are enabled without that variable and a local caller can fetch prompts or spend the evaluator budget without authentication — fix: require configured authentication for these capabilities and explicitly define local-browser origin/Host protections.
F6 [HIGH] backend.md §6 budget accounting — Durable accounting occurs only after an attempted task, not before each chargeable call — scenario: retries occur before their counters are persisted, or the process dies after a paid response; subsequent checks undercount calls/spend — fix: durably reserve and reconcile each attempt, account for uncertain outcomes, and aggregate all attempts rather than only final-response usage.
F7 [HIGH] backend.md §6 budget ceiling — The byte-based token estimate is not specified as a conservative upper bound — scenario: actual billed tokens exceed the projected estimate and a permitted call crosses the claimed hard ceiling — fix: use a defensible upper-bound reservation and documented billing assumptions; validate budget configuration and define reconciliation behavior.
F8 [HIGH] backend.md /evaluate concurrency — Checking a lock before scheduling BackgroundTasks does not atomically reserve a run — scenario: two requests are accepted before either background task holds the lock, and running=false can also be observed by the CLI before execution starts — fix: reserve run ownership in the request handler and expose queued/running/terminal state, preferably with a run identifier.
F9 [HIGH] backend.md §6 routing / AC6b — Capping Retry-After at 30 seconds contradicts honoring the server’s requested delay — scenario: a 429 requests a longer wait and the worker retries early — fix: defer or stop when the requested delay exceeds the run’s wait allowance; define HTTP-date parsing and a single per-provider attempt limit for mixed 429/5xx sequences.
F10 [HIGH] backend.md Part B 0b — A permanently rejected replay blocks the oldest-first spool indefinitely — scenario: a spooled batch later receives 422; replay keeps it and stops on every flush, starving valid batches behind it — fix: apply terminal-rejection accounting/removal to replay too, and define handling for corrupt files and malformed success responses.
F11 [HIGH] backend.md Part B 0b / AC2 — Atomic rename alone does not establish crash durability, and successful-response counters are not a complete crash protocol — scenario: power loss follows rename but precedes durable filesystem writes, losing a supposedly durable batch — fix: specify file and directory fsync, crash recovery, acknowledgement ordering, and counter reconciliation; explicitly bound loss from batches still only in memory.
F12 [HIGH] database.md rollback / backend.md §5 — Code-only rollback preserves prompt data but removes the newly introduced retention worker — scenario: v9 resumes ingestion successfully while retained v10 prompts age beyond expiry without deletion — fix: include a rollback privacy runbook that disables capture and preserves an expiry mechanism or performs an authorized prompt purge.
F13 [HIGH] database.md pre-verification / backend.md Part B 0c — The task-unit and hierarchy requirements can silently degrade — scenario: one task spans multiple user prompts, or missing delegation metadata makes child tasks appear as roots and enter the root-only pilot — fix: require hook-level boundary evidence; make missing hierarchy support a gated decision or represent it as unknown and exclude it from root-only sampling.
F14 [MEDIUM] database.md backfill / backend.md §2 — Complexity provenance is assumed rather than verified — scenario: a non-request-shape complexity value is ingested and labelled request-shape-v1; equal-timestamp events can also produce different baseline choices in backfill and live ingestion — fix: enforce method provenance and use the same deterministic timestamp-plus-event-ID ordering in both paths.
F15 [MEDIUM] database.md AC3b / migration strategy — Aggregate checks do not prove existing rows are unchanged, and backup verification occurs too late — scenario: offsetting token edits preserve SUMs, or an unusable backup is discovered only after migration — fix: compare all original columns by primary key on the clone, verify backup integrity before mutation, and test failed/partial startup recovery across create_all and migrations.
F16 [MEDIUM] backend.md §6 response parsing — Validation omits important distribution and numeric constraints — scenario: negative probabilities still sum to one, or non-finite values survive an insufficient range check and contaminate API/report output — fix: require finite bounded scores/confidence/probabilities, exactly five unambiguously mapped entries, valid legends and nonnegative usage; pin the response fixture before implementation.
F17 [MEDIUM] backend.md §7–8 / summary AC4 — Metadata backfill cannot deliver the proposed pilot, and inactivity is not completion — scenario: historical tasks have no prompts, while a new task paused for an hour is sampled as finished — fix: align the brief with prospective collection, own the collection/start-date gate, and define a terminal-task signal or explicitly approve an inactivity-based proxy.
F18 [MEDIUM] backend.md §7 report — Decision metrics are not required to use a common complete-case cohort or handle undefined statistics — scenario: JEV failures remove difficult tasks only from its cohort, or constant labels make correlation/κ undefined, yet the report compares scores and prints pass/fail — fix: use paired eligible cases, report exclusions and coverage, specify bootstrap seed/degenerate handling, and allow “insufficient evidence.”
F19 [MEDIUM] backend.md Part B 0c / acceptance criteria — Request composition has implementation prose but no explicit correctness AC, and capture can precede backend support — scenario: an older backend acknowledges and ignores the once-only prompt field, permanently losing pilot content; composition fields may also ship with incorrect category attribution unnoticed — fix: gate capture activation on backend readiness and add owned composition/category, truncation and parent/root propagation ACs.
F20 [MEDIUM] backend.md §7 label / labels API — Prompt display and human notes lack dedicated content-safety handling — scenario: a retained prompt emits terminal control sequences during blind labelling, or a labeler stores copied sensitive text indefinitely in note — fix: escape terminal controls before display and either omit notes or apply an explicit redaction/retention policy to them.
