FINDINGS:
F1 [HIGH] spool.py: Spool.maintenance — The fixed 50-file budget always restarts at the oldest files, starving later spool files and dead letters of retention processing; violates AC2e — scenario: 50 unexpired telemetry batches remain pending during a backend/auth outage; file 51 contains a newly expired prompt → every maintenance pass revisits the same 50 files, leaving that prompt on disk beyond its deadline. Fifty pending files also prevent any dead-letter maintenance — fix: sweep all retained prompts at startup and each flush, or use expiry-aware scheduling that guarantees every due file is processed; add tests exceeding the maintenance budget.
F2 [HIGH] sink.py: Sink._send / Sink._replay — The readiness gate applies when attaching a new prompt, but not when transmitting retained prompts — scenario: capture is enabled and a prompt is spooled during an outage; capture is subsequently disabled and the next meta probe reports false, or the plugin restarts with capture_task_prompt=False → replay still POSTs task_prompt_text. Queued prompts likewise survive a negative probe — fix: enforce the config/meta gate at the common transmission boundary and remove prompt text from outgoing copies when capture is not ready; test both queued and replayed batches. This violates AC10b regardless of whether the backend discards the text.
F3 [MEDIUM] spool.py: write_durable / Spool.maintenance — Failed writes can leave prompt-bearing .tmp files that are never maintained until a restart; violates AC2e — scenario: writing a fresh prompt succeeds but fsync or os.replace raises OSError → the caller counts a dropped batch, but the .json.tmp remains. A continuously running worker ignores it after the prompt expires — fix: safely clean up failed temporary writes and include surviving temporary files in recurring retention maintenance; test injected failures without restarting.
F4 [MEDIUM] spool.py: write_durable — A single os.write is assumed to write the entire envelope, so a short write can be committed as a successful durable batch — scenario: os.write returns fewer bytes than supplied under storage pressure → the truncated file is fsynced and renamed, spool() reports success, and replay later discards it as corrupt, losing the batch — fix: loop until all bytes are written, handle zero-progress writes as failures, and fault-test short writes.
F5 [LOW] sink.py: _record_rejections; spool.py: Counters / maintenance — AC2d's malformed-ack detection and drop warnings are incomplete — scenario: a 200 response containing {} is accepted without incrementing malformed_acks; invalid JSON increments that counter without a WARNING; telemetry expiry increments expired_batches without a WARNING. The supplied test checks an overflow warning, not the expiry warning — fix: validate the documented acknowledgement shape and warn on malformed acknowledgements and expiry drops without logging content; add independent counter/log assertions.

UNSURE:
- Review is static and limited to the supplied diff; no repository, test suite, filesystem-failure reproduction, or live endpoint was inspected or exercised.
- Backend acknowledgement schema, replay deduplication after a committed request with a lost response, and compatibility of the meta fields cannot be verified from this part. The fake-client replay test does not establish server-side deduplication.
- The unchanged capture_content path and redaction helpers are not shown sufficiently to establish whether legacy prompt_text can bypass the new prompt-retention protections.
- The Drift Log requires subagent_stop registration, but neither the callback map nor plugin.yaml adds it; its required lifecycle behavior is not specified here, so the resulting runtime impact is uncertain.

VERDICT: Request changes: retention starvation and ungated transmission of retained prompts are high-confidence privacy/contract defects; durability and observability gaps also need coverage.
