- tokenInspector, Hermes core içine gömülmeyecek.

- Provider'ın gerçek modeli ile requested model ayrıştırılmalı.

## 1.3 Kritik gerçek durum tespitleri

1. **Canlı DB migrate edilmemiş.** `token_inspector.db` hâlâ ilk commit şemasında: `complexity` ve `prompt_text` kolonları bile yok, `journal_mode=delete`, 4 event / 22 pricing row.

9. **Analytics tamamı Python tarafında.** `_fetch()` tüm satırları ORM nesnesi olarak (3KB'a kadar `prompt_text` dahil) belleğe çekiyor. `GET /api/events` de tüm satırları çekip Python'da dilimliyor.

# 2. Mimari Brainstorm ve Seçeneklerin Değerlendirmesi

## 2.1 Idempotency stratejisi

| Seçenek | Değerlendirme |
|---|---|
| A. SELECT-then-INSERT (mevcut) | ❌ Yarış koşullu, IntegrityError yakalanmıyor, batch'te N commit |
| B. SELECT + `IntegrityError` yakala + yeniden SELECT | ✅ Doğru ama tek event için 3 sorgu, batch'te savepoint gerekir |
| C. `INSERT ... ON CONFLICT DO NOTHING` + sonrasında tek `SELECT` ile id çözümleme | ✅✅ Yarış koşulu DB'ye devredilir, batch tek transaction, tek commit |

**Karar: C.** SQLite 3.24+ (`ON CONFLICT DO NOTHING`) gerektirir; sistemde 3.45.1 var, Python 3.13 hedefinde güvenli. `INSERT OR IGNORE` kullanılmayacak — o NOT NULL ihlalini de sessizce yutar. Unique hedef: **`(project_name, client_event_id)`** partial index (`WHERE client_event_id IS NOT NULL`).

`client_event_id` yoksa dedupe yok — bu bilinçli. Sunucu tarafında içerik hash'inden türetilmiş sahte bir key **üretilmeyecek** (aynı prompt'un iki gerçek çağrısı meşrudur).

**Retry ↔ attempt ilişkisi:** her provider API denemesi ayrı bir event'tir (her biri ayrı faturalanır). Dolayısıyla `client_event_id` **attempt numarasını içermek zorundadır** (`<session>:<turn>:<span>:<attempt>`). `attempt`/`retry_count` yalnızca metadata; dedupe anahtarı değil.

## 2.2 Batch semantiği

| Seçenek | Değerlendirme |
|---|---|
| A. Event başına commit (mevcut) | ❌ N fsync, kısmi başarısızlık belirsiz |
| B. Tek transaction, hepsi-ya-hiç | ❌ Tek bozuk event tüm buffer'ı reddeder → client sonsuz retry döngüsü |
| C. Tek transaction, satır bazlı sonuç raporu, doğrulama hatası olanlar reddedilip diğerleri yazılır | ✅✅ |

**Karar: C.** Yanıt her zaman `200`, gövdede satır bazlı `inserted` / `duplicate` / `rejected` + `index`. Client buffer'ı yalnızca `rejected` olmayanlar için güvenle boşaltır. Batch üst sınırı **500 event**; aşımda `422`.

## 2.3 Maliyet modeli — token sınıfı semantiği (en kritik karar)

Provider'lar `prompt_tokens`'ı farklı tanımlar:

| Provider | `prompt_tokens` cache içerir mi? | `completion_tokens` reasoning içerir mi? |
|---|---|---|
| Anthropic | **Hayır** (`input_tokens` cache'ten ayrık) | Evet (thinking, `output_tokens` içinde) |
| OpenAI | **Evet** (`prompt_tokens_details.cached_tokens` alt küme) | Evet (`reasoning_tokens` alt küme) |
| Gemini | **Evet** (`cachedContentTokenCount` alt küme) | Evet (thoughts) |

Sunucu bunu tahmin **etmeyecek**. İki açık kural:

1. **Sözleşme:** `prompt_tokens` = tam input fiyatından faturalanan, cache **hariç** token sayısı (Anthropic yerleşimi kanonik kabul edilir).
2. **Açık normalizasyon bayrağı:** `input_tokens_include_cache: bool = false`. `true` gönderilirse sunucu `prompt_tokens -= (cache_read + cache_creation)` (0'a clamp) uygular ve normalize edilmiş değeri saklar. OpenAI/Gemini client'ları bu bayrağı `true` gönderir. Tahmin yok, sessiz düzeltme yok.
3. **`reasoning_tokens` daima `completion_tokens`'ın alt kümesidir; maliyete ayrıca eklenmez.** Üç provider'da da böyle. `reasoning_tokens > completion_tokens` gelirse clamp + `cost_status_reason` işaretlenir.

**Maliyet formülü:**

```
cost = prompt*input + completion*output + cache_read*cache_read_price + cache_creation*cache_creation_price
```

**`cost_status` (yeni kolon) — sessiz yanlış tahmini bitirir:**

| Değer | Anlam |
|---|---|
| `priced` | Kural bulundu; sıfırdan farklı her token sınıfının fiyatı tanımlı |
| `partial` | Kural var ama bir sınıfın fiyatı **NULL** → o sınıf maliyete katılmadı |
| `estimated` | Yalnızca `total_tokens` vardı → `avg(input,output)` yaklaşımı kullanıldı |
| `unpriced` | Model için kural yok → `estimated_cost_usd = NULL` |
| `legacy` | Migration ile geriye dönük doldurulan eski satırlar |

Ayrıca `cost_status_reason` (kısa slug: `no_rule`, `total_tokens_only`, `cache_price_missing`, `reasoning_clamped`).

**Kritik yan karar:** `cache_read_price_per_1m` / `cache_creation_price_per_1m` **NULL-able** olmalı. Şu anki `0.0` default'u "ücretsiz" anlamına gelir ve `partial` durumunu tespit etmeyi imkânsız kılar. `NULL = bilinmiyor`, `0.0 = ücretsiz` ayrımı zorunlu.

## 2.4 `model` vs `model_requested` vs alias

Üç ayrı kavram, üç ayrı kolon:

- `model_requested` — çağıranın istediği (`claude-sonnet-latest`, `gpt-5.4`)
- `model` — provider'ın gerçekten çalıştırdığı/raporladığı (`claude-sonnet-4-6-20260210`)
- `pricing_model` — fiyatlama için **çözümlenmiş** anahtar (`claude-sonnet-4-6`)

Çözümleme sırası: `model` → `model_aliases` tablosu → tarih son-eki soyma (`-\d{8}$`) → `model_requested` → `unpriced`. Ham string asla değiştirilmez; yalnızca `pricing_model` türetilir. Bu, geriye dönük recost'u mümkün kılan tek tasarım.

> ⚠️ **Pydantic uyarısı:** `model_requested` alanı `model_` protected namespace ile çakışabilir (Pydantic <2.10'da `UserWarning`). `EventIn` ve `TokenEvent`'e `model_config = ConfigDict(protected_namespaces=())` eklenecek.

## 2.5 pricing_version ve recosting

Ingest-anında-maliyet kararı korunuyor (mimari sabit). Ama recost hazırlığı için:

- `pricing_rules.pricing_version INTEGER` — her upsert'te artar.
- `token_events.pricing_version` — kullanılan sürüm event'e damgalanır.
- `POST /api/settings/recost?dry_run=true` — varsayılan olarak yalnızca `unpriced|partial|estimated|legacy` satırlarını yeniden hesaplar, farkı model bazında raporlar; `dry_run=false` uygular.

Ham token sayıları saklandığı için recost kayıpsızdır. `priced` satırlar varsayılan olarak **dokunulmaz** (tarihsel doğruluk korunur).

## 2.6 Ham içerik: hash-first

- `prompt_hash` (sha256 hex, **client tarafında** hesaplanır) + `prompt_length` (karakter) **daima** saklanır.
- `prompt_text` yalnızca `STORE_RAW_PROMPTS=1` iken saklanır; aksi halde ingest'te düşürülür (client göndermiş olsa bile).
- **Sonuç:** `complexity_scorer.py` varsayılan olarak devre dışı kalır (girdisi olmaz). Bu doğru — skorlayıcı ham prompt'u Anthropic API'sine gönderiyor; hash-first politikasında bu opt-in olmalı. Alternatif yol açık: client `complexity`'yi kendisi gönderebilir.
- **Credential koruması:** `tags` içinde anahtarı `/(key|token|secret|password|auth|credential|bearer)/i` ile eşleşenler ingest'te **düşürülür**; `error_message` 512 karaktere kırpılır; hiçbir log satırında payload gövdesi veya header değeri basılmaz.

## 2.7 Analytics: SQL-side aggregation

Tüm `by-*` endpoint'leri `func.sum/count/avg` + `GROUP BY`'a taşınacak. Tarih kovaları `substr(recorded_at,1,10)` (gün) / `substr(recorded_at,1,13)` (saat) — `granularity` stub'ı böylece gerçekten çalışır. `GET /api/events` gerçek `LIMIT/OFFSET` + ayrı `COUNT(*)` kullanacak ve `prompt_text`'i varsayılan olarak yanıttan çıkaracak.

Her agregasyon yanıtı artık üç ayrı sayı döner: `total_cost_usd` (yalnızca `priced`), `estimated_cost_usd` (yalnızca `estimated`+`partial`), `unpriced_event_count`. Belirsizlik grafikte tek bir sayıya karışmaz.

## 2.8 Index politikası (yazma maliyeti)

Mevcut kısmi implementasyon 10 kolona index koyuyor — her INSERT'te 10 ek B-tree yazımı. Bu, tek yazarlı SQLite için gereksiz yük.

**Karar — tutulacak:** `project_name`, `model`, `recorded_at`, `session_id`, `trace_id`, kompozit `(project_name, recorded_at)`, unique `(project_name, client_event_id)`.

**Kaldırılacak `index=True`:** `provider`, `tool_name`, `span_id`, `parent_span_id`, `turn_id`, `api_request_id`, `client_event_id` (kompozit unique zaten kapsar). Bunlar ya tarih-filtreli tarama içinde grup anahtarı ya da düşük seçicilikte.

## 2.9 Migration mimarisi

`try/except: pass`'li ALTER yığını terk edilecek. Yerine **versiyonlu, idempotent, sesli-hata-veren** mini runner (`migrations.py`):

- `schema_migrations(version INTEGER PK, applied_at TEXT)` tablosu
- Her migration `(version, fn)`; `fn` `PRAGMA table_info` ile kontrol edip uygular
- Her biri kendi transaction'ında; hata → **exception fırlat**, uygulamayı başlatma
- Alembic **kullanılmayacak** (tek dosyalık kişisel araç için aşırı ağırlık)

## 2.10 Auth / ingest header

Yerel araç; varsayılan auth yok kararı korunuyor. Ama:

- `INGEST_TOKEN` env değişkeni **set edilmişse** ingest route'ları `X-Ingest-Token` ister; `hmac.compare_digest` ile karşılaştırılır; uyuşmazsa `401`. Token asla loglanmaz.
- `X-Project-Name` doğrulanır: `^[a-z0-9][a-z0-9._-]{0,63}$`, aksi halde `422` (kardinalite patlaması koruması).
- README'deki `--host 0.0.0.0` → **`127.0.0.1`** olacak. Auth'suz bir servisi LAN'a açmak gereksiz.

## 2.11 Hermes tarafı (kapsam dışı ama sözleşmeyi belirler)

Kararlar korunuyor: gömme yok, plugin var, ortak LLM lifecycle hook hattı, proxy katmanı ayrı karar. Bu plan yalnızca **sunucu sözleşmesini** ve `token_inspector_client.py` referans client'ını kapsar. Client, çağıran sürecin sıcak yolunu bloke etmeyecek: paylaşımlı `AsyncClient`, sınırlı `asyncio.Queue` (dolu ise **event düşürülür**, çağıran beklemez), arka plan drain görevi, **her seviyede tam istisna yutma**.

# 8. Riskler ve Edge-Case'ler

| # | Risk / edge-case | Etki | Azaltım |
|---|---|---|---|
| 1 | **Ortam hazır değil** — venv yok, `fastapi` import edilemiyor, `__pycache__` cpython-311 (sistem 3.12) | İlk komutta duvara toslanır | **İlk görev**: `python3 -m venv .venv` + `requirements*.txt` kurulumu; `.venv/` gitignore'a |
| 2 | **SQLite tek yazar** — WAL yazar-yazar eşzamanlılığını çözmez | Çok sayıda Hermes plugin örneği → `database is locked` | `busy_timeout=5000` + client tarafında kuyruk/batch; ADR'de "tek yazar" sınırı yazılı |
| 3 | Mevcut DB'de mükerrer `client_event_id` (kolon yeni olduğu için bugün imkânsız, ama ara sürümü çalıştırmış DB'lerde mümkün) | UNIQUE index oluşamaz | v6 açık hata + mükerrer listesi; kullanıcı manuel temizler |
| 4 | **Cache write TTL varyantları** (Anthropic 5dk=1.25×, 1sa=2×) tek fiyat kolonuna sığmıyor | 1 saatlik cache maliyeti eksik hesaplanır | Bilinen sınır; `tags.cache_ttl` ile kaydedilir, ADR'de yazılı. v2'de ikinci kolon |
| 5 | **Provider token semantiği yanlış eşlenirse** cache token'ları çift sayılır | Maliyet %30–50 şişer/eksilir | `input_tokens_include_cache` bayrağı; client helper'da provider bazlı normalizasyon; `test_cost.py` regresyonu |
| 6 | `estimated` maliyetlerin grafiklerde `priced` ile karışması | Yanlış model kararı | Analytics'te üç ayrı alan; `routing-recommendations` yalnız `priced`; dashboard'da uyarı banner'ı |
| 7 | **Alias çözümlemesi gerçek modeli maskeleyebilir** | Fiyat değişikliği fark edilmez | Ham `model` her zaman saklanır; `pricing_model` ayrı kolon; `unpriced-models` endpoint'i düzenli kontrol |
| 8 | **Recost geri alınamaz** | Tarihsel maliyet kaybı | `dry_run=true` varsayılan; `priced` satırlara varsayılan dokunmama; öncesinde `.bak` |
| 9 | **Dashboard XSS** — ingest edilen string'ler `innerHTML`'e giriyor | Kötü niyetli/bozuk client dashboard'da script çalıştırır | `escapeHtml()` + inline `onclick` kaldırma; ingest'te alan uzunluk sınırları |
| 10 | **`--host 0.0.0.0` + auth yok** | LAN'daki herkes veri yazıp okuyabilir | Varsayılan `127.0.0.1`; uzaktan erişim isteniyorsa `INGEST_TOKEN` zorunlu |
| 11 | **Complexity scorer ham prompt'u Anthropic'e gönderiyor** | Hash-first politikasıyla çelişir | `STORE_RAW_PROMPTS=1` arkasına alınır; README'de açık uyarı |
| 12 | **Saat kayması** — client `occurred_at`'i gelecekte/geçmişte | Timeseries kovaları bozulur | `recorded_at` (sunucu) analitikte kanonik; `occurred_at` yalnız korelasyon; >24sa sapma `tags`'e not düşülür |
| 13 | `attempt`'i `client_event_id`'ye koymayan client | Retry'ler tek event'e katlanır, gerçek maliyet eksik görünür | Sözleşmede açık kural + README örneği + client helper'ın otomatik eklemesi |
| 14 | Sınırsız `session_id`/`tags` kardinalitesi | DB şişmesi | Uzunluk sınırları + `tags` anahtar sayısı sınırı; retention politikası v2'ye bırakılır |
| 15 | **Pydantic `model_` protected namespace** | Import'ta gürültülü uyarı (Pydantic <2.10) | `ConfigDict(protected_namespaces=())`; alternatif: kolon adı `requested_model`, API alanı alias |
| 16 | `create_all` + manuel migration ikiliği yeni DB'de sürüm damgasını atlayabilir | Migration'lar boş DB'de yeniden koşar | Yeni DB `create_all` sonrası **doğrudan en son sürümle** damgalanır; migration'lar zaten idempotent |
| 17 | `ON CONFLICT DO NOTHING` SQLite 3.24+ gerektirir | Çok eski Python derlemelerinde hata | Startup'ta `sqlite_version` kontrolü + açık hata mesajı (mevcut: 3.45.1) |
| 18 | Client kuyruğu dolduğunda event düşürme | Telemetri kaybı | Bilinçli takas: **Hermes asla bloke olmaz**. Düşen sayacı loglanır (içerik değil) |
