# Per-project prompt/JEV allowlist with clone path-deny, and a safe producer example (O10)

SLUG: prompt-allowlist-safe-producer

## TASK_SUMMARY
Add a per-project allowlist for task prompt capture and JEV scoring. It is off by default, and any project that is unknown or ambiguous is off. Prompts are captured and stored only for proven root tasks; child (subagent) sessions never carry a prompt (plan-review r2 simplification; child metadata is unchanged). It is enforced in three places: in the Hermes plugin before queue/spool (plus a path deny rule for `-devir` hand-off clones, and a strip of already-queued/spooled prompts when a session later turns out to be a child), at backend ingest (spool replay included; a task that becomes `child` loses its stored prompt), and in the JEV worker just before any provider send. Also make the README `push_token_event` helper and `token_inspector_client.py` into a safe producer example: send the token, check status and ack, count losses, use a bounded queue and an idempotent `client_event_id`, and send no prompt text or free-form error text. This closes Open Item O10, which blocks the task-telemetry Activation Gate.

## ACCEPTANCE_CRITERIA
- AC1 (plugin default off): with `capture_task_prompt: true` and the `/api/meta` probe ready but an empty or missing plugin allowlist, no event in the queue, spool or HTTP body carries `task_prompt_text`, for any project, the `hermes` fallback included.
- AC2 (plugin allow): with project X on the plugin allowlist, a root turn attributed to X, via any source (alias, git_remote, git_root, hook_metadata, `explicit_marker`, `session_assignment` or `hermes` fallback), carries its scrubbed prompt exactly as before. A turn attributed to a project not on the list carries none.
- AC3 (path deny beats allowlist):
  - With X allowlisted, a session whose resolved workspace path (any `_runtime_cwds()` candidate, or any ancestor of one) matches `~/Projects/*-devir` or a configured extra glob carries no prompt, even though its origin slug equals X.
  - Symlinked paths are matched after resolve.
  - No path or glob text appears in any event, tag or log line.
  - (F7) An empty candidate set, or any exception while resolving candidates or globs, means denied, verified through the full hook → sink path.
- AC4 (root-only rule, plugin; r2):
  - A prompt is attached only when, at attach time, the session is positively classified `root`, its project is allowlisted and its own resolved workspace is not path-denied.
  - (r1 F2, kept) A session is `root` only if this process saw its `on_session_start` and no `subagent_start` names it. A session named by `subagent_start` is a `child`. Anything else is `unknown`. Holds after registry loss (restart, TTL expiry, eviction) and for a reset/reused session id without a new `on_session_start`.
  - A `child` never carries a prompt, whatever its own project, cwd or parent. The same holds for grandchildren and for `unknown`. Child events keep their metadata (`task_hierarchy='child'`, parent fields, tokens) as today.
  - r1 F3 → resolved by the root-only rule (r2): there is no ancestor walk, cached parent decision or depth limit. r2 F5 → resolved the same way: a reused parent id cannot re-enable a child.
  - (r2 F4, documented behaviour) The workspace is checked for each new request state. A root whose cwd later moves into a denied dir keeps the prompt already attached to its current turn. Its later turns get none, and `denied` stays sticky for the session.
- AC5 (plugin spool replay): events already in the spool are replayed without `task_prompt_text` if their project is no longer on the current plugin allowlist, if they lack the current eligibility marker (AC14), or if their session was revoked as a late child (AC16). The metadata event is still delivered.
- AC6 (backend ingest):
  - With the backend allowlist env empty or unset, an event carrying `task_prompt_text` is accepted (201/200, counted in `inserted`) but no prompt is stored on `tasks`.
  - With X allowlisted, X's root-turn prompt is stored as before.
  - Behaviour is the same for `/api/events`, `/api/events/batch`, and replayed or duplicate deliveries.
  - A not-allowed prompt never reaches `token_events` or `tasks`.
  - (F12) No 4xx/validation response (single or batch) and no log line echoes prompt text.
- AC7 (backend root-only rule; r2):
  - (r2 F6) A prompt is stored only for a **proven root**: the upserted task row has `hierarchy_status='root'`, `parent_task_ref IS NULL`, and `root_task_ref IS NULL OR root_task_ref = id` (`root_task_ref` never points at another task). Its project must also be allowlisted. The data model and `_upsert_task` are unchanged.
  - A `child` task (parent fields, or `task_hierarchy='child'` alone) or an `unknown` task never stores a prompt. No parent row is consulted.
  - r1 F4 → resolved by the root-only rule (r2): no transitive walk.
  - (r1 F5 / r2 F1, F7) When a task becomes `child` after its prompt was stored, the prompt is nulled via the purge path (`prompt_text = NULL`, `prompt_purged_at` set, `secure_delete`) in the same transaction, and it is never re-stored. Only the task's own upsert can make it `child`, so no descendant walk is needed. An allowlist change alone never purges.
- AC8 (JEV gate):
  - Just before any provider call, the worker skips any task whose project is not on the backend allowlist at run time or which is not a proven root (AC7). Recorded `error_type` is `project_not_allowed`.
  - (r2 F8) The status depends on timing. If the gate trips before the first provider attempt of that task, the status is `skipped`. If it trips after an attempt already started (a retry or fallback), the status is `error`. The budget ledger and `evaluator_attempts` hold only the attempts that were really made.
  - No provider request is made after the gate trips; a mocked transport records zero calls for a pre-attempt skip.
  - Removing a project from the env and restarting blocks its already-stored tasks from JEV without purging them.
  - (r1 F6) The check runs before **every** provider attempt (retry and fallback included) and reads the allowlist at call time. A task becoming `child` or a list removal during a run stops further requests.
- AC9 (`/api/meta`):
  - `/api/meta` exposes the allowlist state as `configured` or `empty` and never lists names.
  - An empty backend allowlist is visible (e.g. a disabled reason or a separate field; the Planner picks one and updates the Activation Gate text to match).
  - The existing `config_errors` / disabled-reason contract used by the plugin probe keeps working.
  - (F15) By flags and precedence: flags off + empty list → reason stays `not_enabled`, `task_prompt_allowlist: empty` and a `no_allowed_projects` `config_errors` entry (preflight); flags on + empty list → reason `no_allowed_projects` unless a higher-priority error exists.
  - (F14) Allowlist configuration never appears in `/api/meta`, logs or events; project names in normal telemetry and the authenticated `allowed_only` results are permitted.
  - (r2 F10) Invalid backend allowlist entries are dropped with one fixed startup WARNING, `invalid allowlist entries ignored`, that has no count and no names. The plugin drops invalid entries silently.
- AC10 (plugin error text): the plugin no longer emits `error_message` on any event path (`mapping.py` 252/286 and any others). It emits `error_type` and `http_status` only. The backend still accepts `error_message` from older producers (existing tests stay green).

## RISKS

- R3: the clone location is overridable (`HERMES_DEVIR_REPO`). A clone outside `~/Projects/*-devir` is missed unless an extra glob is added. Document this.
- R4: if the explicit prompt marker (`project_markers`, disabled by default) is ever enabled, a user-typed marker could attribute a turn to an allowlisted project. Path deny still wins, but name-based D10 protection weakens. Doc note only.
- R5 (r2): children never carry a prompt, so subagent prompts are never stored or scored. This is an accepted data loss by design (the JEV pilot samples roots only), not a leak.
- R6 (F13, residual of the Q4 decision): `error_type` is identifier-restricted, not categorised, so an identifier-shaped secret or name can still pass. The session discriminator uses a fixed category list instead. Documented, not fixed.
- R7 (F2): sessions whose `on_session_start` this plugin process did not see (e.g. after a gateway restart) are `unknown` and send no prompt until a new session starts. Accepted data loss. When `subagent_start` arrives after a session's first call, the plugin strips its queued and spooled prompts (AC16), and the backend nulls a stored one when the task becomes `child` (AC7). Accepted residual (r2 triage): a prompt that reached the local spool or DB before the late `subagent_start` (an in-flight batch, or a crash before the worker's rewrite) exists locally until the rewrite or null runs. hermes is local, and JEV never sends it because non-roots are skipped.
- R8 (F10): an unconfirmed delivery (`transport_unconfirmed`) may have been committed by the server; it is reported apart from confirmed loss, not as a loss.
- R9 (r2 F4): a root whose cwd moves into a denied dir keeps the prompt already attached to its current turn; its later turns are re-checked and get none. Documented, not fixed.
