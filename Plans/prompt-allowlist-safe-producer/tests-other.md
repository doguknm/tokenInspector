## Environment and Conventions

- **Backend** (`C:\Users\Bentego_Admin\Projects\tokenInspector`): pytest (`asyncio_mode = auto`) with the existing `tests/conftest.py` `client` fixture (temp `DB_PATH`, `lifespan(app)`, `httpx.ASGITransport`, Host `test` allowed, engine disposed per test — RP 6).
  - `STORE_TASK_PROMPTS`, `JEV_ENABLED`, `AI_GATEWAY_API_KEY`, `INGEST_TOKEN`, `TASK_PROMPT_ALLOWED_PROJECTS` are unset by default. Tests set them with `monkeypatch.setenv` and then call `features.refresh()` (the startup evaluation); capture tests use the existing `_enable_capture` pattern in `tests/test_task_ingest.py` (32-char token, valid purge interval).
  - JEV tests reuse the fake clock/sleep and scripted `post_evaluation` helpers of `tests/test_jev_worker.py` (import them or move them to a shared helper without behaviour change). A recording transport counts provider calls.
  - Commands (Windows): `python -m pytest -q`, `python -m py_compile *.py routes/*.py scripts/*.py`, `node --check static/app.js`, `git diff --check`.
- **Plugin** (`C:\Users\Bentego_Admin\Projects\token_inspector`): pytest in the plugin `tests/`. Reuse the `_hooks` / `_call` / `CapturingSink` helpers of `tests/test_capture_0c.py`.
  - `_hooks` gains `allowed=()` and `deny=()` parameters that build `PluginConfig(capture_task_prompt=..., task_prompt_allowed_projects=frozenset(allowed), ...)`, and it resets `_session_roots`, `_denied_sessions`, `_subagent_state`, `_project_state`, `_prompt_sent` per test. A helper `_start(sid)` calls `_on_session_start(session_id=sid)` (root evidence, B3.3); `_child(sid, parent)` calls `_subagent_start(child_session_id=sid, parent_session_id=parent, parent_turn_id=...)`.
  - **Assertion boundaries (r2 F9).** Plugin tests name where they assert: at `CapturingSink` (the event handed to `_emit`, plus the `prompt_authorized` value it received — isolates the attach gate from the Sink's redundant strips), at a real `Sink` queue item (isolates emit), in the HTTP body of a fake client (isolates `_send`/`_post`), or in spool file bytes read after a worker pass whose fake client raises `ConnectError` (isolates the spool rewrite from replay). Backend JEV gate tests insert task rows directly with SQL when the ingest gate would otherwise mask the JEV gate.
  - `project._runtime_cwds` is monkeypatched with a stub accepting `strict` and returning `tmp_path`-based directories, so results never depend on where the repo is checked out; `HOME` and `USERPROFILE` are monkeypatched to `tmp_path` for default-glob tests.
  - **Existing tests that expect a prompt** (`test_prompt_sent_once_per_turn_scrubbed_with_capture_time`, the spool/transmission prompt tests, etc.) must now allowlist the resolved project and call `_start(sid)`; backend prompt tests send `task_hierarchy="root"` and `prompt_eligibility="v1-allowed"`. This is an expected consequence of default-off, not drift; list the touched tests in the status.md Verification Log.
  - Run locally (`python -m pytest -q`) **and** on hermes: push the branch to the `hermes` remote, then on hermes clone that branch into a temp dir, create a Python 3.13 venv, install `requirements-dev.txt`, run `python -m pytest -q`, delete the temp dir. The hermes plugin working copy and the installed plugin are never touched. Symlink tests may skip on Windows when `os.symlink` raises `OSError`; they must pass on hermes.
- **No real network**: backend uses ASGI transport; JEV and the safe client use `httpx.MockTransport`; the plugin uses a fake client/transport capturing POST bodies.
- **Privacy assertions (F12)** use a canary: prompt `ZZ-ALLOWLIST-CANARY-<n> please use sk-ant-CANARYSECRET0123456789 at /srv/private/x` (`<n>` unique per test; the `ZZ-…` marker is never redacted), tmp paths, and glob strings. Tests assert **both** that the `ZZ-…` marker is absent **and**, independently, that the prompt field is absent/NULL (`task_prompt_text` key in event/body/spool, `tasks.prompt_text`). They search event dicts (as JSON), spool file bytes, HTTP bodies, `caplog` text (level DEBUG), 4xx/validation response bodies, and for backend the DB + `-wal` bytes.
