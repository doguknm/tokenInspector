# Hermes code review r1 — part 1/3 (backend code + docs), 2026-09-28

FINDINGS:
F1 [HIGH] docs/adr/002-task-prompt-retention-and-jev.md §6 R7; jev_scorer.py — “JEV never sends it” is not guaranteed for the accepted late-child residual — scenario: a prompt reaches the backend while its task is classified as root; evaluation runs before the delayed child metadata arrives → the marker, allowlist and proven-root checks all permit sending it; a later purge cannot undo that send — fix: explicitly document and obtain acceptance of this external-send window, or establish a final classification signal before scoring; do not claim the root check prevents sends before child classification.
F2 [MEDIUM] jev_scorer.py evaluate_task — The retention check precedes the per-attempt project gate, giving the wrong AC8 error_type for a late child — scenario: after an initial provider attempt, the task becomes child and ingest nulls its prompt; the retry reads the purged row → returns prompt_purged before reaching project_gate, rather than project_not_allowed — fix: run project_gate before the per-attempt retention checks, preserving skipped/error based on actual attempts; test a real child transition and purge between attempts.
F3 [MEDIUM] token_inspector_client.py post_event/_send — Enqueue validation does not match HTTPX JSON serialization, so one invalid event can poison a batch and misclassify confirmed loss — scenario: a dict contains float("nan"); json.dumps(payload) accepts it, but HTTPX rejects non-finite JSON before transport → every event in that batch is counted as transport_unconfirmed although none was sent — fix: validate using wire-equivalent serialization, including allow_nan=False and UTF-8 encoding, before enqueue; count the invalid event as serialization_failed and verify valid neighboring events still send.
F4 [MEDIUM] README.md “Batch ingest” — The example treats a structurally valid rejection ack as success and does not implement the advertised loss accounting — scenario: a 2xx response contains inserted=0, duplicates=0, rejected=3 → valid_ack returns true and ok becomes true despite every event being rejected; malformed JSON instead raises without accounting — fix: use the bounded client, or explicitly handle response parsing, count inserted/duplicates as delivered and rejected as loss, and distinguish malformed acknowledgments from non-2xx responses.
