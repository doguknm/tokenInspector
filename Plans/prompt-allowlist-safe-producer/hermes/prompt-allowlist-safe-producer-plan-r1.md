FINDINGS:
F1 [BLOCKER] backend.md B3.5–6 / AC3–5 — Emit and replay enforce project membership but not path denial or parent eligibility — scenario: a pre-upgrade spool contains a prompt from an allowlisted project's -devir clone or denied parent's child → replay posts it; the backend cannot distinguish it from an allowed root — fix: define fail-closed handling for legacy envelopes without eligibility provenance and enforce path/ancestry eligibility at emit and replay, without persisting paths.
F2 [BLOCKER] backend.md B3.2–3 / AC4 — Missing child registration is treated as a root, not an unknown-parent child — scenario: restart, TTL expiry, eviction or delayed subagent_start removes the child's _subagent_state entry; its current cwd/project are allowed → decision becomes allowed despite a denied or unknown parent — fix: require positive root/child classification; unknown lineage must suppress capture, and test registry loss and hook reordering.
F3 [HIGH] backend.md B3.3 / AC4 — Cached allowed parent decisions do not establish current transitive eligibility — scenario: root becomes denied after its child was marked allowed; a grandchild consults only the child's cached allowed decision → capture proceeds — fix: invalidate descendants or revalidate a bounded ancestor chain; test eligibility changes, stale decisions and session-ID reuse.
F4 [HIGH] backend.md A2–A3 / AC7–8 — Backend ancestry checks are not transitive; JEV also accepts a child with no root reference if its immediate parent passes — scenario: allowed-project grandchild points to an existing allowed-project child whose own parent is missing, with root_task_ref null → ingest stores its prompt and JEV permits it — fix: validate ancestry to a proven root with cycle/depth guards; missing or inconsistent ancestry must fail closed.
F5 [HIGH] backend.md A2 / tests-other.md AC7 — The plan handles child classification established before prompt arrival, but not afterward — scenario: a prompt is stored while the task appears root, then a later event identifies a missing-parent child → disallowed-child text remains stored — fix: define ordering/provenance requirements before initial storage and explicit handling of subsequent hierarchy changes; add prompt-before-parent-fields tests.
F6 [HIGH] backend.md A3.2 / AC8 — The authoritative check is before prompt loading and reservation, not explicitly before every provider send — scenario: a retry occurs after hierarchy changes, or an old worker remains active during an allowlist-removal restart → a previously approved task can still be sent — fix: specify checks at every outbound attempt plus worker cancellation/draining across configuration generations; test retry and in-flight removal behavior.
F7 [HIGH] backend.md B2 / tests-other.md AC3 — Empty workspace candidates and candidate-resolution failures lack an explicit fail-closed contract — scenario: runtime_candidates returns no usable paths → path_denied's loops can return false and an allowlisted project captures; resolution exceptions occur before entering path_denied's try block — fix: treat missing/unresolved workspace evidence as denied or unknown and test the complete hook-to-sink path, not only Path.resolve inside the helper.
F8 [HIGH] backend.md A5.3 / AC11–12 — Ack validation accepts impossible counts — scenario: batch size one receives inserted=0, duplicates=0, rejected=0, negative counts, or boolean values accepted as Python ints → loss accounting reports success or becomes invalid; README success needs only rejected==0 — fix: require non-boolean, nonnegative integers whose sum equals batch size, applying the same validator to both examples.
F9 [HIGH] backend.md A5.4 / tests-other.md AC11 — Dict resends violate the stable-ID requirement — scenario: caller posts the same ID-less dict twice after an uncertain delivery → each copy receives a new UUID and both can insert — fix: expose a reusable prepared event/ID, require IDs for dict inputs, or otherwise guarantee identity across resends; the current test explicitly permits behavior contrary to AC11.
F10 [MEDIUM] backend.md A5 / AC11 — “Every lost event” is neither fully specified nor exactly observable — scenario: server commits but the response is lost → transport_failures counts a delivered event as lost; shutdown cancellation or serialization failure can leave queued events outside the listed counters — fix: distinguish confirmed rejection from unconfirmed delivery, define shutdown/drain and serialization handling, and test cancellation, close and invalid payloads.
F11 [MEDIUM] backend.md A5 README helper / KEY_CONSTRAINTS — The helper has a timeout but no stated bounded asynchronous delivery mechanism — scenario: callers await each HTTP operation or schedule unbounded helper tasks → telemetry either delays callers or creates unbounded outstanding work — fix: make the helper delegate to the bounded client, or explicitly implement bounded enqueue, worker lifecycle and queue-full accounting.
F12 [HIGH] tests-other.md privacy assertions / AC1, AC3, AC6 — The shared canary contains a secret that the existing scrubber may remove, so absence of that canary does not prove absence of prompt storage; backend log/validation-response leakage is also untested — scenario: the gate fails but redaction removes the canary while ordinary prompt text reaches storage, or a validation error echoes the request → privacy tests can miss it — fix: include a unique non-redacted marker and assert prompt-field absence/nullness independently; inspect logs and error responses for malformed single and batch requests.
F13 [MEDIUM] backend.md B4 / Shared definitions — Identifier syntax is not a guarantee that free-form text, secrets or names cannot escape — scenario: reason="SecretProjectName" or an identifier-shaped credential passes _identifier and enters finish_reason/error_type; the safe client likewise retains arbitrary error_type — fix: preserve the user's Q4 decision but state its residual limitation accurately; for the newly added session discriminator handling, use fixed recognized categories and add identifier-shaped canaries.
F14 [MEDIUM] backend.md Shared definitions / A4 / AC9 — “Allowlist names … never enter events … HTTP responses” contradicts normal project attribution and the allowed_only endpoint — scenario: allowlisted project x appears in an ordinary event and in authenticated allowed_only results, revealing membership by design — fix: distinguish prohibited disclosure of configuration/path evidence from permitted project metadata and authenticated membership filtering; define and test that precise boundary.
F15 [MEDIUM] backend.md A1 / AC9 / tests-other.md AC9 — Disabled-reason requirements disagree — scenario: allowlist empty with flags off → A1 and tests require not_enabled, while AC9 unconditionally requires no_allowed_projects; higher-priority configuration errors also override it — fix: qualify AC9 by flags and precedence, and use config_errors plus task_prompt_allowlist for the flags-off preflight contract.
F16 [HIGH] status.md P2–P3 / backend.md deployment constraints — No cross-repository upgrade/rollback safety procedure owns legacy queues, spools and active workers — scenario: an older plugin replays denied-clone prompts to the upgraded backend, or rollback restores code that ignores configured allowlists while capture flags remain enabled → protection disappears — fix: assign an owner and ordered compatibility checks, provenance-safe backlog handling, worker draining and a mandatory flags-off rollback procedure; this needs no schema migration or automatic purge of retained tasks.
F17 [MEDIUM] tests-other.md AC2, AC8, AC13 / status.md — Verification does not fully cover the stated contract — scenario: explicit_marker/session_assignment attribution, an unlisted root with an allowed immediate parent, or missing R1 documentation regresses → listed tests/manual checks need not catch it — fix: add those cases, restart/eviction and lifecycle cases above, and an explicit semantic AC13 checklist owned by final review; make O10 resolution contingent on completed verification rather than the earlier docs step.
UNSURE:
- Review is based only on the supplied plan. No repository inspection, test execution, network access or PEGA verification was performed.
- Existing normalization, hook ordering, hierarchy-upsert rules, retry behavior and auth implementations are not supplied; their actual protections or bypasses cannot be established here.
- Q1's claim that cross-project lookup “always misses” depends on identifier guarantees not supplied; a same-project row with matching parent session/turn identifiers could defeat that assumption. This does not reopen the accepted fail-closed decision.
- Legacy prompt_text/error_message acceptance is explicitly retained and out of scope; therefore the plan cannot establish a universal “no prompt text anywhere” guarantee for arbitrary or older producers.
VERDICT: Changes required before implementation approval: replay provenance, lost child lineage and incomplete ancestry enforcement leave concrete privacy gaps; the user's Q1–Q5 decisions and accepted R1 remain unchanged.
