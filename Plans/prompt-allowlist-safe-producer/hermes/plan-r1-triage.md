# Plan review r1 — triage (user decision 2026-09-27: fix all 17; run round 2)

Raw findings: `prompt-allowlist-safe-producer-plan-r1.md`. Q1–Q5 decisions and accepted risk R1 are unchanged.

| F | Decision | Fix to apply in the plan |
|---|---|---|
| F1 | fix | At emit, the plugin marks every event that still carries `task_prompt_text` with an eligibility marker (e.g. `prompt_eligibility: "v1-allowed"`, no path or config data). On replay and on every send, it strips `task_prompt_text` from any event without the current marker, which covers legacy/pre-upgrade spool files. The backend also treats a prompt without the marker as not eligible (fail-closed), so an older plugin cannot deliver one. |
| F2 | fix | Positive classification. A session counts as `root` only if this plugin process saw its start (a session start or first turn with no pending `subagent_start` for it). A session known only through `subagent_start` counts as a child. Anything else counts as `unknown`, which means off. Test registry loss (restart, TTL expiry, eviction) and hook reordering (`subagent_start` arriving after the child's first call). |
| F3 | fix | Do not rely on a cached parent decision alone. At each prompt attach, walk the ancestor chain (bounded depth, e.g. 8, with a cycle guard): every ancestor must be known and allowed and not path-denied. A missing link means off. Test an eligibility change, a stale decision and session-id reuse. |
| F4 | fix | The backend child rule becomes transitive: walk `parent_task_ref` links up to a proven root (bounded depth, cycle guard). Every node must exist and belong to an allowed project. A missing, inconsistent or null `root_task_ref` means off, at ingest and in the JEV gate. |
| F5 | fix | When a task's hierarchy changes to `child` (or its ancestry changes) after a prompt was stored, re-evaluate eligibility. If it is not eligible, null the prompt (same path as purge: `prompt_purged_at`, secure_delete). Test prompt-before-parent-fields ordering. |
| F6 | fix | JEV: evaluate allowlist + ancestry eligibility immediately before every provider attempt (retry and fallback included), reading the allowlist at call time. Treat a config change across restart as a new generation: in-flight runs re-check before each attempt. Test retry after a hierarchy change, and removal while in flight. |
| F7 | fix | Empty workspace candidates, or any exception while resolving candidates or globs, means denied (fail-closed). Test the full hook → sink path, not just the helper. |
| F8 | fix | Ack validator: `inserted`, `duplicates`, `rejected` must be non-bool, non-negative ints summing to the batch size. Anything else goes to `malformed_acks`. The README example uses the same validator. |
| F9 | fix | A dict input without `client_event_id` gets the generated uuid4 written back into the caller's dict (and into the dataclass), so a resend reuses it. Test: the same ID-less dict posted twice produces one insert. |
| F10 | fix | Counters distinguish confirmed loss (`rejected`, `non_2xx`, `queue_full`, `serialization_failed`, `dropped_on_close`) from unconfirmed delivery (`transport_unconfirmed`). Define close/drain behaviour. Test cancellation, close and an invalid payload. |
| F11 | fix | The README helper becomes a thin wrapper that enqueues into the bounded client (a single module-level client). It never awaits HTTP on the caller's path. |
| F12 | fix | Privacy tests use a unique non-redactable marker (e.g. `ZZ-ALLOWLIST-CANARY-<n>`) in addition to the secret. They assert the prompt field is absent or null independently, and check logs and 4xx/validation responses for single and batch requests. |
| F13 | fix | Keep the Q4 decision. Document the residual limitation (an identifier-shaped secret can still pass). The session-event `reason`/`error` discriminator uses a fixed category list instead. Add identifier-shaped canaries to the tests. |
| F14 | fix | Restate the boundary. Allowlist *configuration*, globs and paths never appear in events, logs or `/api/meta`. Project names in normal telemetry and in the authenticated `allowed_only` filter are permitted. Test that boundary. |
| F15 | fix | Qualify AC9 by flags and precedence. With the flags off, the reason stays `not_enabled`, and an empty allowlist appears as `task_prompt_allowlist: empty` plus a `config_errors` entry (preflight). With the flags on, the reason is `no_allowed_projects` unless a higher-priority error exists. Align A1, AC9 and the tests. |
| F16 | fix | Add an upgrade/rollback runbook to status.md, owned by Claude with deploy approval from the user. Order: backend first (its gate protects against old plugins), then plugin install + gateway restart with no agent job running. Legacy spool is handled by the F1 marker rule. Rollback always starts by turning the flags off. No schema migration, no automatic purge. |
| F17 | fix | Add tests for `explicit_marker` / `session_assignment` attribution, an unlisted root with an allowed immediate parent, restart/eviction/lifecycle, and a semantic AC13 checklist owned by the final review. O10 is resolved only after the final review passes, not after the docs step. |
