## Task summary
One plan in three phases, with a commit/push checkpoint after each phase.
- **Phase 1** tags every hermes-agent LLM event with launcher job context: `job_ref`, `runtime`, `work_type` and `job_attempt`. These go in `tags` and carry no content. It adds cost per job (one job → many task_refs) and fixes the cross-project parent defect in `task_store._upsert_task`.
- **Phase 2** adds a stdlib-only Claude Code producer under `producers/claude_code/`. It covers Windows sessions and `claude -p` hand-off (devir) runs on hermes, and comes with a written cross-source dedup authority.
- **Phase 3** ships a versioned, read-only JSON/CSV export contract (API plus a dashboard download) that PossibleSkills consumes.

## Key constraints
- Privacy and storage:
  - CLAUDE.md: "Raw prompts, responses, and tool arguments are off by default." and "Absolute workspace paths and complete Git remote URLs must not enter telemetry storage."
  - AGENTS.md: "Never persist raw response bodies or tool arguments. Never send absolute workspace paths, complete remotes, credentials, private network identifiers, or authenticated payloads."
  - D8 §5 forbidden fields: prompt text, response text, tool args/output, file paths, free error text, rule XML, internal hostname/IP, case/run IDs. Allowed: identities, work type, provider/model, token/cache counters, duration, status, closed error class, tool **names** (offered ≠ executed).
  - D10: prompt capture and JEV are definitively off for PEGA projects, devir clones and their subtasks. The new CC producer never sends prompt text under any condition. STORE_TASK_PROMPTS and JEV_ENABLED stay off.
  - The plugin sends no `error_message`; the CC producer sends none either — only restricted `error_type` / `http_status`.
- Idempotency, schema and producer behaviour:
  - `client_event_id` is idempotent per project (partial unique SQLite index). SQLite requires WAL, `busy_timeout`, foreign keys and additive migrations.
  - Cache-read, cache-creation, reasoning, prompt and completion tokens remain distinct. Unknown pricing is `unpriced/no_rule`, never free.
  - Ingest stays fail-open for producers; validation stays strict at the backend.
  - Producers stay bounded, short-timeout, asynchronous, fail-open and privacy-first. Hermes core is not modified.
- Consumer contract (AGENTS.md "What the numbers mean"):
  - A root task excludes its children, so summing tasks counts each call once.
  - Evaluator (JEV) usage is stored under project `token-inspector` with `task_id` NULL; never a task, excluded from task totals.
  - `request_tool_names_json` lists tools offered, not tools run; executed tools never go there.
  - Wall time is not queue time nor end-to-end job time; there is no job-duration event.
- Identity, validation and safety:
  - Allowlist names: exact after `strip().lower()`, must match `^[a-z0-9][a-z0-9._-]{0,63}$`.
  - Never normalize with the plugin's `normalize_project_name` (falls back to `hermes`). An invalid `parent_project_name` is dropped, never normalized.
  - Validation errors never echo input; this also applies to export errors.
  - Online SQLite backup before any scoped corrective change; dry-run first.
  - SQLite files, backups, `.env`, secrets, raw logs and transcripts are never committed or mirrored. Tests build synthetic transcripts in `tmp_path`.
- Identity mapping: D8 §1 says `project` is the real repo name; TI keeps lowercasing `X-Project-Name`; aliases are mapped on the consumer side. The export documents lowercase names.
- Deployment and tests: a plugin reinstall needs `hermes gateway restart`; Windows hook commands use `python`, not `python3`; run the suite on hermes before a deploy (Recurring Problem 11).
- Shared files: `~/.claude/settings.json` (Windows and hermes), the three `hermes.sh` copies and the `/hermes` skill change only through SESSION-COORDINATION.md. Our hook entries must coexist with PossibleSkills' planned global PreToolUse coordination hook.
- Reviews: hermes plan review 1 round; hermes code review 1 round; Claude integration review (Opus) once at the end.

## Acceptance criteria

### Phase 1 — job correlation and cross-project child fix
- **AC1.1 (verification gate, first task):** a read-only check records whether `hermes -z` loads plugins in its own process, so launcher env vars reach the plugin. If yes: proceed. If no: implementation stops and the user is asked (scope change); the default proposal is a launcher-posted job→session mapping record (D8 §6 "separate mapping record").
- **AC1.2:** a job launched through any of the three `hermes.sh` copies produces llm events whose tags carry `job_ref`, `runtime=hermes-agent`, `work_type` (when the launcher supplies one) and `job_attempt` (when supplied). Job context comes from launcher env vars read by the plugin; one shared env contract for both producers.
- **AC1.3:** backend normalization of the reserved keys never rejects an event: `work_type` outside {brainstorm, review, code, devir, k1, k2, other} becomes `other`, a missing value stays absent; a `job_ref` failing a strict id regex is dropped; a `job_attempt` that is not an integer ≥ 1 is dropped; `runtime` outside the closed D8 list is dropped. `job_attempt` is separate from `EventIn.attempt` (per-call retry).
- **AC1.4:** the measured worst-case plugin tag payload, including all new keys, passes `_clean_tags`; a test pins that size. The backend with the new cap is deployed before the plugin that sends the new keys.
- **AC1.5:** a cost-per-job API returns one row per `job_ref`: distinct task count, runtime(s), work_type, attempts seen, the four token sums, `cost_usd` over priced calls only (null if none), `unpriced_count`, `estimated_cost_usd`, first and last event time. JEV usage is excluded. A job with unpriced calls is never shown as complete or zero. A task belongs to at most one job; a conflicting later `job_ref` is counted as an anomaly and does not overwrite.
- **AC1.6:** the dashboard shows the cost-per-job table with the same semantics (frontend lane, frontend-design skill), with a browser test.
- **AC1.7:** cross-project child hierarchy: a child in project B whose event carries a valid `parent_project_name=A` gets `parent_task_ref = task_ref(A, parent_session, parent_turn)` and the correct root, in either arrival order. The re-root UPDATE no longer filters by project. An absent or invalid `parent_project_name` gives exactly today's behaviour. `child` is never downgraded. No child stores a prompt; O10 tests pass unchanged.
- **AC1.8:** a repair script for existing rows: dry-run by default, online backup before apply, idempotent; re-links dangling `parent_task_ref` / `root_task_ref` by hash matching and reports counts only. *(Pending user confirmation.)*
- **AC1.9:** no new field or tag carries prompt text, paths, hostnames or free error text; a sentinel test asserts this for plugin payloads.

### Phase 2 — Claude Code producer and dedup authority
- **AC2.1 (verification gate, read-only, no content copied):** record the real transcript and hook facts on local transcripts and write the chosen rules into the plan: hook stdin fields for Stop / SubagentStop / SessionEnd; subagent transcript layout; repeated lines per `message.id` during streaming and which line holds the final usage; resumed-session copies; `<synthetic>` model lines.
- **AC2.2:** in a Windows Claude Code session, after each turn's Stop hook, that turn's assistant calls appear as `llm_request` events with `runtime=claude-code@windows`, `producer=claude-code-hook`, the model, `prompt_tokens` excluding cache plus distinct cache_read, cache_creation and completion tokens, one task per user turn, and the project resolved by alias env → sanitized origin slug → git root name → fallback.
- **AC2.3:** a `claude -p` devir run started by `hermes.sh devir-baslat` on hermes produces events with `runtime=claude-code@hermes`, `work_type=devir` and `job_ref` = the devir job id. The project is `pegadocrag` (origin slug; ADR-002 R2). No prompt text is sent.
- **AC2.4:** dedup: `client_event_id` is derived from provider `message.id` + `requestId`, not from the session. Re-running a hook, multiple transcript lines with the same message id and resumed-session copies are each counted exactly once, and ack `duplicates` reflects it.
- **AC2.5:** subagent runs become child tasks linked to the parent turn via `parent_session_id` / `parent_turn_id`.
- **AC2.6:** privacy, checked with a byte-level sentinel test over every emitted payload: no transcript text, `cwd`, `transcript_path`, git branch, tool inputs/outputs, skill/agent names or hostname. Only fields on an explicit allowlist are sent. `request_tool_names` stays null; `tool_call_count` may be sent.
- **AC2.7:** fail-open: on backend down, timeout, 401, 422 or a malformed transcript, the hook exits 0 within a fixed bound and never blocks Claude Code. The read cursor advances only after a valid ack (at-least-once plus idempotent insert). Local state holds only offsets and ids and is bounded.
- **AC2.8:** works with `INGEST_TOKEN` unset (today) and set (after the Activation Gate). The token is read from env or a local secret file, never logged or committed.
- **AC2.9:** the installer does an idempotent merge into `~/.claude/settings.json` on Windows and hermes, preserves every other hook (including PossibleSkills' PreToolUse), and offers dry-run/diff, backup and uninstall. The change is announced in SESSION-COORDINATION.md before it is applied.
- **AC2.10:** the dedup authority is written in an ADR and enforced: one counting producer per runtime (hermes-plugin → hermes-agent; claude-code-hook → claude-code@windows and claude-code@hermes); within CC, the transcript usage record wins over hook-derived data.
- **AC2.11:** `producers/claude_code/` is stdlib-only (import test). Tests run on Windows and hermes. AGENTS.md "Coverage" is updated.

### Phase 3 — versioned read-only export
- **AC3.1:** versioned read-only endpoints serve jobs, tasks and llm-call events as JSON. The dashboard offers CSV download with the same field set. No writes, no auth; works with `INGEST_TOKEN` unset.
- **AC3.2:** an explicit allowed-field list per dataset, including an allowlist of tag keys; a contract test fails if any other field appears. Excluded: prompt text, label notes, legacy `error_message`, tool args, `prompt_hash`, `user_id_hash`, full `tags`, paths and hostnames. The export does not reuse `GET /api/events` as-is.
- **AC3.3:** timestamps are UTC ISO-8601 `Z`; `from` inclusive, `to` exclusive, both echoed in the envelope. An invalid range returns a documented static error body with no input echo.
- **AC3.4:** keyset pagination with stable ordering, `next_cursor` and a partial/complete marker. Concatenated pages equal the full result, with no duplicates or gaps under concurrent ingest.
- **AC3.5:** the envelope carries `generated_at`, the covered period, staleness (latest ingested `recorded_at` per runtime) and `coverage` (runtimes measured and not measured in the period).
- **AC3.6:** units documented: token counts as integers, cost in USD with `cost_status`. Zero, unknown (null) and absent (not measured / not applicable) are distinct and never collapsed (D8 §3).
- **AC3.7:** stable ids and a consumer dedup rule: event id, `task_ref`, `job_ref`, plus the documented CC `client_event_id` rule. Tasks and jobs carry `updated_at`; open rows can change and should be re-fetched.
- **AC3.8:** `docs/export-contract-v1.md` is versioned separately from the app and the DB schema. `schema_version` changes only on a breaking change; consumers must ignore unknown fields. Error and timeout responses, max page size and range limits are documented.
- **AC3.9:** CSV cells are protected against formula injection (leading `= + - @`). There is a browser test for the download.

## Recommended approach
**Phase 1.** Keep job context in `tags`, as PA asked. Add backend normalization of the reserved keys (`job_ref`, `runtime`, `work_type`, `job_attempt`, `producer`) that drops or normalizes values but never rejects an event. First measure the worst-case plugin tag bytes, then raise only the `_clean_tags` byte cap (weak recommendation: 1024 bytes, keys stay ≤ 20). Do not drop `project_source` / `project_confidence`. Deploy the backend before the plugin. For the parent fix, add a validated `parent_project_name` body field (not stored) that `_upsert_task` uses for `parent_ref`, and remove the project filter from the re-root UPDATE.

**Phase 2.** A short-lived hook process reads only the new part of the transcript, sends synchronously with a short timeout, and advances its cursor only on a valid ack (at-least-once; the idempotent insert makes it safe without a spool). Attribution logic matches the plugin's, guarded by a parity test as for `redaction.py`.

**Phase 3.** A new read-only router with an explicit field allowlist and keyset pagination, plus a separate contract doc. Record the job-correlation contract, the dedup authority and the export contract in ADRs.
