# Hermes plan review r1 - Part B (summary + frontend + tests-other + tests-e2e + status)

FINDINGS:
F1 [HIGH] tests-other.md Phase 2 / AC2.7 — Concurrent hook invocations have no specified state-safety test — scenario: overlapping Stop and SessionEnd read the same cursor, then the slower process overwrites newer offset/turn state; pruning can also race active writers → replay or incorrect turn attribution — fix: backend owns bounded per-transcript coordination and atomic state replacement; test overlapping hooks, stale writers, lock timeout, pruning and process termination.
F2 [HIGH] tests-other.md test_streaming_lines_counted_once_with_final_usage — Final-usage dedup is tested only within one read — scenario: an initial usage record is acknowledged before a later line updates the same message/request → the later event is a duplicate and final tokens are lost — fix: C0 must establish an observable finalization rule; test streaming groups split across reads, hooks and bounded batches before advancing past them.
F3 [HIGH] tests-other.md test_cursor_advances_only_on_valid_ack — Advancing on an ack containing rejected events silently weakens at-least-once delivery — scenario: a valid batch ack reports one rejected call → cursor advances and that call is never retried or visibly accounted for — fix: distinguish acknowledged insertion/duplicate from rejection; specify retry versus deliberate drop policy with bounded, content-free loss counters and tests.
F4 [HIGH] tests-other.md Phase 2 cursor/fail-open tests — Cursor recovery and whole-process bounds are insufficiently exercised — scenario: transcript truncates below the saved offset, or a large backlog/deep subagent scan exceeds the deadline before any successful checkpoint → calls remain permanently unread — fix: backend owns replacement/truncation detection, bounded reads and incremental progress; test large/oversized records, blocked stdin, slow local operations and restart after termination, not only a hanging HTTP server.
F5 [HIGH] tests-other.md test_rerun_and_resume_count_once / AC2.4 — Global-sounding CC dedup conflicts with project-scoped uniqueness — scenario: a copied/resumed call resolves to another project after an alias/origin change → identical client_event_id is inserted again under the other project — fix: define stable project attribution for replayed calls or explicitly narrow the dedup guarantee; test changed project resolution and missing/changed requestId.
F6 [HIGH] tests-other.md test_runtime_producer_pairing + test_legacy_events_inferred_runtime — Invalid-runtime removal collides with legacy inference — scenario: a mismatched CC producer pair has runtime dropped but remains stored, then export interprets its missing runtime as legacy hermes-agent → incorrect coverage and potentially duplicate counted usage — fix: distinguish genuine legacy records from invalid modern pairs; define counting eligibility separately from fail-open ingestion and test ingest → jobs → export together.
F7 [HIGH] tests-other.md export pagination / status.md v12 snapshot decision — ingest_seq bounds new inserts, not mutations of existing rows or task attribution — scenario: between pages a recost changes old events, repair re-roots tasks, or a previously unassigned task gains its first job → the same cursor chain changes totals or membership — fix: backend/database must define snapshot behavior for these mutations, implement preservation or static cursor invalidation, and test each case across events/tasks/jobs.
F8 [HIGH] summary.md AC1.9/AC2.6/AC3.2 / privacy tests — Key allowlists and name regexes do not establish value privacy — scenario: an allowed model, project, session identifier or syntactically valid job_ref contains a hostname, path-like content or secret → the allowlist still forwards it; current canaries mainly occupy excluded fields — fix: define provenance and value rules for every exported/emitted identifier and string; inject canaries into allowed fields and verify payloads, headers, exports and state.
F9 [HIGH] tests-other.md migration tests / status.md Rollback — The promised code-only rollback/re-upgrade path is not covered end to end — scenario: v10 code ingests into v12, a restart backfills NULL sequences, and an old export cursor is reused → omissions or changed snapshot membership may occur; listed schema-rollback tests do not establish compatibility — fix: database owns a v10→v12→old-code writes→v12 test, interrupted-backfill recovery, preserved non-NULL sequences, dedup checks and an explicit cursor lifetime/invalidation rule.
F10 [HIGH] tests-other.md repair tests / status.md Deploy Runbook — Repair lacks specified concurrent-write and cycle cases despite running after service restart — scenario: a candidate parent changes after analysis, or a match would create a cycle → apply uses stale hierarchy or corrupts roots; separately sampled backup/source counts can disagree during ingest — fix: backend owns transactional revalidation and cycle refusal; test concurrent ingest, self/descendant matches and repair failure atomicity, and verify backup consistency against a coherent snapshot.
F11 [MEDIUM] tests-other.md AC1.2/AC2.3 / status.md Final check — Launcher acceptance lacks complete evidence ownership — scenario: plugin env unit tests and one live review job pass while one of the other hermes.sh copies or devir-baslat never exports the contract — fix: assign synthetic execution checks for all three launcher copies, the skill handoff and devir-baslat; track each live AC separately as pending until observed, without requiring PEGA access here.
F12 [MEDIUM] frontend.md State Management / tests-e2e.md — UI request races and export termination are unspecified or untested — scenario: a slower old filter request overwrites the newest Jobs result, or a superseded export keeps fetching despite “ignored results” → incorrect table or unnecessary unbounded work — fix: use request-generation checks/abort, freeze export parameters per run, stop superseded loops, and test repeated cursors, page failures, row cap, cancellation and delayed responses.
F13 [MEDIUM] tests-e2e.md — Several explicit frontend ACs have no exercising fixture — scenario: four Jobs rows never test page navigation and the small export never tests next_cursor; tab/CR guarding, partial-cost badges and mixed work types can regress while the suite passes — fix: add deterministic multi-page Jobs/export cases and targeted cases for these branches, including empty exports and exact range boundaries.
F14 [MEDIUM] frontend.md export error status — Rendering arbitrary response.error is not a closed error policy — scenario: a nonconforming error body includes free text or a hostname in error → the UI displays it despite the fixed-error requirement — fix: map a local allowlist of documented codes to fixed messages and use a generic fallback for unknown codes, invalid JSON and network failures; test canary-bearing responses.
F15 [MEDIUM] frontend.md Jobs anomaly line / tests-other.md conflict tests — The UI says “N task(s)” but tests establish only one conflicting event — scenario: one task receives multiple distinct conflicting calls → an event-counting job_ref_conflicts counter can be presented as several affected tasks — fix: define separate conflicting-event and affected-task counts or change the wording; test repeated distinct conflicts and duplicate delivery.
F16 [MEDIUM] tests-other.md Phase 2 / status.md Phase Checkpoints — Phase 2 explicitly adds a plugin attribution fixture and runner but its checkpoint says “— (no plugin change)” — scenario: backend parity tests pass locally while plugin additions are neither committed nor pushed — fix: include the Phase 2 plugin changes in checkpoint ownership and require cross-repo fixture comparison in integration verification rather than allowing it to skip there.
F17 [MEDIUM] tests-other.md CM10 / mutation policy — The silent-success mutation targets a failure-only test — scenario: printing only after successful ingestion survives test_hook_exits_zero_on_every_failure → the declared mutation gate cannot validate its control — fix: add a successful subprocess test asserting empty stdout/stderr and target it explicitly; require evidence for each mutation’s intended branch.
F18 [MEDIUM] status.md PLAN_BASE, Hermes Code Review, O5 — Plan-lock prerequisites remain unresolved placeholders — scenario: implementation starts with no backend diff base, no finalized one-round review specification and an unconfirmed shared-file owner → final review scope or authorized launcher coverage is incomplete — fix: make base capture, review-spec completion and S1 ownership explicit blocking tasks before their dependent work; remove stale “pending confirmation” and per-phase-deploy wording already superseded by decisions.
UNSURE:
- Part A was not supplied: exact endpoint field compatibility, schema/index/rollback SQL, repair transaction design, producer limits and snapshot implementation cannot be verified; the findings above identify requirements or coverage gaps visible in Part B, not observed implementation defects.
- Actual Claude Code hook/transcript behavior and hermes -z plugin loading remain C0/J0 gates; no repository, transcript, runtime or PEGA verification was performed.
- Whether job/task filtering aggregates full lifetime or only in-window calls, and whether staleness is global or period-scoped, is not settled by the supplied summary; tests should pin both semantics.
VERDICT: Changes required before plan lock: close the counting, cursor, privacy and snapshot gaps, reconcile checkpoint ownership, and retain the single post-review deploy with live checks explicitly pending.
