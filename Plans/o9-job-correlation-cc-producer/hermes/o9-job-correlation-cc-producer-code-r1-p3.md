TAG: `o9-job-correlation-cc-producer-code-r1-p3` · prompt: backend code 3/5 — Claude Code producer: hook, state, client, config, installer (S5 = installer code).

FINDINGS:
F1 [HIGH] producers/claude_code/cc_state.py:acquire/release — Stale-lock takeover is a check-then-unlink race, so multiple hooks can own the same transcript simultaneously — scenario: A and B both observe an expired lock; A deletes it and creates its replacement; B then deletes A’s replacement and creates another; both enter process_file, and either release can delete the other’s lock. The load/check/replace checkpoint sequence is then no longer serialized and can regress — fix: use a process-owned OS lock released on process death; add a deterministic simultaneous-takeover test.
F2 [HIGH] producers/claude_code/cc_hook.py:_run/process_file — Direct processing ignores an existing checkpoint’s stored context and substitutes the current launcher context for unsent records — scenario: job A’s POST fails, leaving pending records and ctx=A; the same transcript is resumed under job B, and its next hook sends A’s backlog with job_ref=B and overwrites the checkpoint context — fix: preserve original context for pending usage, with an explicit boundary separating backlog from new-context records; test failed delivery followed by a resume under a different job.
F3 [MEDIUM] producers/claude_code/install.py:run backup creation — Backup names have only second precision and write_bytes overwrites an existing backup — scenario: install and uninstall apply within the same UTC second; uninstall overwrites the original pre-install backup with the installed settings, destroying the original recovery copy — fix: create uniquely named backups exclusively, and test two changing applies with a fixed timestamp.
F4 [MEDIUM] producers/claude_code/install.py:hook_command — Double quotes do not safely quote arbitrary installation paths for the shell — scenario: on Linux, an installation directory literally containing `$HOME` causes shell expansion inside the generated command, so Claude invokes a nonexistent/different hook; backticks or `$()` in a directory name can execute shell substitutions — fix: use platform-appropriate shell escaping and test literal metacharacters in hook paths.
F5 [MEDIUM] producers/claude_code/cc_hook.py:module imports/main — The watchdog starts only after all module-level imports finish, leaving startup outside the advertised five-second bound and fail-open handler — scenario: loading a producer module from a stalled filesystem takes over five seconds before main starts; no watchdog exists yet, and the installed hook timeout is ten seconds. An import failure likewise occurs outside the exception handler and emits a traceback with a nonzero exit — fix: protect startup with an outer launcher/deadline and handle producer import failures inside the fail-open boundary; test delayed and failing imports.
