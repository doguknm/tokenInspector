# Hermes plan review r1 - Part A (summary + database + backend)

FINDINGS:
F1 [BLOCKER] backend.md X2/J5 — The snapshot does not freeze job membership because attribution joins live tasks.job_ref — scenario: page 1 captures as_of while a task has no job; a later event assigns it job A → pre-snapshot calls enter A, changing membership and sums on subsequent pages — fix: derive job assignment from events bounded by as_of, or materialize snapshot membership; test late assignment and conflicting assignments between pages.
F2 [HIGH] database.md v12 — MAX(ingest_seq)+1 is not permanently monotonic across deletions — scenario: the highest-sequence rows are removed between export pages, then ingest reuses a sequence ≤ the saved as_of → new data enters the old snapshot — fix: use a persistent transactional high-water allocator that survives deletion, or explicitly enforce and test a no-deletion invariant for the snapshot lifetime.
F3 [HIGH] backend.md C2/C3 — Bounded read windows can split a message group before its final usage — scenario: an early duplicate is before the byte/record limit and its final usage is after it → the early record is inserted and the final record is discarded as a duplicate — fix: never commit a group without verified finality; preserve pending group state or defer the group, and test splits at both limits.
F4 [HIGH] backend.md C5/C6/C7 — Whole-window acknowledgement conflicts with the watchdog and provides no guaranteed progress — scenario: earlier batches succeed but later requests repeatedly exhaust the watchdog → every hook retransmits the same prefix and never reaches the tail — fix: checkpoint acknowledged contiguous record boundaries within the budget, with group-safe batching; test repeated interruption and eventual progress.
F5 [HIGH] backend.md C2/C5/C7 — Truncation, oversized lines and final-hook backlog have no recovery contract — scenario: a transcript is replaced with a shorter file, a complete line exceeds the read cap, or SessionEnd leaves more than one window → records remain unread indefinitely — fix: define content-free file-generation detection, bounded oversized-line handling and a bounded retry/drain mechanism, or explicitly document and obtain approval for loss.
F6 [HIGH] backend.md C5 — Backend dedup does not make concurrent cursor writes safe — scenario: a slower hook overwrites a newer offset/turn_uuid with an older checkpoint; simultaneous eviction or temporary-file writes interfere → progress regresses or state is lost — fix: use bounded per-transcript serialization or generation-aware monotonic checkpoint updates, unique temporary files and coordinated eviction; verify fail-open lock contention.
F7 [HIGH] backend.md C3/C4/C10 — Session-independent client_event_id does not ensure dedup across project attribution changes — scenario: a resumed copy resolves through a new alias or different cwd → the same provider call is accepted under another project by the project-scoped unique index — fix: define and enforce stable project ownership for CC provider-call identities, or introduce CC-specific cross-project dedup; test alias changes and resumed copies.
F8 [HIGH] backend.md C10/X4 — Dropping runtime neither prevents counting nor preserves dedup authority — scenario: an event with a mismatched producer loses runtime but still enters job totals and export, where it is inferred as hermes-agent → unauthorized-source usage is counted and misclassified — fix: distinguish genuinely historical untagged events from newly invalid pairs, and define a non-counting treatment without rejecting ingestion.
F9 [HIGH] backend.md C3/X4 — Field-name allowlists are not sufficient value-level privacy controls — scenario: a model/session identifier contains a path or hostname, or historical error_type contains free error text → the permitted field is emitted/exported unchanged — fix: specify safe value contracts for every exported string, closed error classes and omission/pseudonymization for unsafe identifiers; test sentinels inside allowed fields, not only forbidden keys.
F10 [HIGH] backend.md C9/S5 — Printing a full settings.json diff can expose unrelated secrets and paths — scenario: diff context includes another hook command containing credentials or an internal URL → private configuration reaches terminal/review logs — fix: show an operation summary or redacted diff limited to owned entries; keep the complete backup local and out of synchronization.
F11 [HIGH] backend.md C9 — Hook ownership and installation atomicity are insufficiently defined — scenario: another command also ends in cc_hook.py", or another session edits settings between read and write → uninstall removes an unrelated hook or apply overwrites another session’s change — fix: identify the exact owned command/entry, preserve mixed hook containers, and use an atomic write with an unchanged-source check.
F12 [HIGH] backend.md J7 — Repair needs a coherent candidate graph and explicit invalid-chain outcomes — scenario: a proposed parent itself needs repair, has a missing ancestor, or forms a cycle → traversal order changes the selected root or reaches an unspecified termination path — fix: compute the proposed graph before writes, reject ambiguous/cyclic/depth-exceeded components, resolve roots deterministically and verify postconditions; report counts for each skipped class.
F13 [HIGH] backend.md J7 — Candidate discovery and backup verification are not tied to the apply transaction — scenario: live ingest changes a candidate after analysis, or changes counts during backup verification → stale relinks are applied or a valid backup is rejected — fix: verify backup consistency against its own coherent snapshot and recompute/revalidate repair candidates under the write transaction before applying.
F14 [HIGH] backend.md X4/X6 — updated_at does not reliably identify aggregate changes — scenario: repair changes a job’s conflict/hierarchy context or recost changes exported costs without a new event → job updated_at, defined only as maximum recorded_at, stays unchanged — fix: define a revision timestamp covering every mutation affecting exported rows, or explicitly remove its change-detection promise and prescribe full replacement/refetch semantics.
F15 [HIGH] backend.md X2/X4 — Event export can disagree with canonical job accounting — scenario: a task belongs to A but a later event carries conflicting job B → J5 counts its cost under A while the exported tag reports B — fix: export the canonical job consistently; if useful, expose the reported job separately with explicit conflict semantics and an allowlisted field.
F16 [MEDIUM] backend.md X2–X4 — Several consumer-facing rules remain contradictory or unspecified — scenario: one task has multiple runtimes/work types, or an event is not a task turn → task runtime/work_type have no selection rule and task_ref is specified as both null and absent — fix: finalize cardinality, inference and null/absent rules per dataset before frontend and contract tests are implemented.
F17 [MEDIUM] backend.md X2/X3 — Period semantics can conceal ongoing work and include out-of-period costs — scenario: a job starts before from but runs during the period → jobs omits it while events includes its calls; a job starting within the period includes later calls beyond to — fix: explicitly name this a start-time cohort export, document reconciliation limitations and test boundaries, or use period-event membership/sums consistently.
F18 [HIGH] backend.md C0/C8 — The verification gate cannot silently override mandatory acceptance criteria — scenario: local transcripts do not establish hook timing/fields or a reliable parent link → “C0 rule wins” allows unlinked children despite AC2.5 — fix: specify admissible read-only evidence for each fact and make missing evidence or incompatible findings a stop-and-user-decision gate, not automatic drift.
F19 [MEDIUM] backend.md C2/C3/C8 — Subagent task identity and failed-call coverage are incomplete — scenario: a child transcript has no user-turn UUID → turn_id is undefined; an assistant error is present → hard-coded success misstates it or the record is silently skipped — fix: define a stable child turn identifier and verified success/error/unknown mapping, including explicit coverage limits for calls without usage.
F20 [HIGH] database.md v11/v12 rollback — Rollback instructions lack version-order and restored-code safeguards — scenario: rollback_v11 runs on the final v12 database → schema version 12 remains recorded while required task columns are gone; current code restarts and cannot repair the mismatch — fix: guard exact source versions, specify reverse migration order and matching application artifacts, and test rollback/re-upgrade from the final combined release.
F21 [MEDIUM] database.md v12 self-heal/compatibility — Startup healing and fallback requirements are underspecified — scenario: run_migrations has already ended its transaction, or SQLite lacks window-function support → “inside the migration transaction” is unavailable or the fallback still fails — fix: assign an explicit transactional startup hook and exact NULL-only offset numbering; establish minimum SQLite versions separately for forward migration and DROP COLUMN rollback.
F22 [MEDIUM] backend.md J5 — Aggregation/filter semantics can produce duplicate counts or inconsistent totals if implemented literally — scenario: a task has several events → summing its conflict counter after the event join multiplies anomalies; filtering a mixed-runtime job before aggregation changes its total — fix: aggregate task conflicts independently and specify whether runtime/work_type select whole jobs or filter constituent calls, with mixed-job fixtures.
F23 [MEDIUM] summary.md / backend.md deployment wording — The brief still suggests a Phase 1 backend deployment and asynchronous producers while the lane specifies deferred production changes and a synchronous hook — scenario: phase checkpoints are treated as deploy permission or “never blocks” is tested as zero waiting → execution violates the locked rollout or an untestable AC — fix: state one final deploy with backend-first installation inside it, and define the approved bounded synchronous hook latency.
