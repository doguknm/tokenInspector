=== FIX A — the agent-name policy is not re-applied on the state-load path ===

Today `producers/claude_code/cc_state.py::load` already runs `_valid_ctx`, but `_valid_ctx` only checks the
agent block's SHAPE (`_AGENT_RE`, `agent_source` membership, run-key shape, policy version). It does not
re-apply the custom-name rule. So a label that was accepted when it was resolved (mode `allowlist`, exact
allowlist member) survives in state even after the operator revokes the allowlist, and a later drain sends
that now-denied name. The plan requires the rule at **state load** as well as resolution
(`cc-agent-complexity-plan.md`, A4 step 7: "Apply the rule at producer resolution, state load, ingest, and
read/export serialization").

Fix: import `cc_agent` in `cc_state.py` and, inside `_valid_ctx`, after the shape check passes, run the
stored label back through `cc_agent.sanitize(...)` with the CURRENT config, and store the sanitized result:

- `mode` = `TOKEN_INSPECTOR_AGENT_NAME_MODE` (or file `agent_name_mode`), defaulting to `"deny"` when
  absent/invalid — read it the same way `cc_config` documents, but do NOT import `cc_config` from
  `cc_state` if that would create a cycle; if a cycle appears, read the two values locally in `cc_state`
  with a tiny helper that mirrors `cc_config`'s rule (env overrides file; only `deny`/`allowlist`;
  allowlist = a JSON array of strings, non-strings dropped).
- `allowlist` = the resolved allowlist tuple.
- `local_names` = a detected-local-identifier set. `cc_attribution` already exposes `local_names()`
  (hostname/FQDN/IPv4-shaped candidates); import it lazily inside the function to keep module load light.
- The `sanitize` call must be applied ONLY to labels that could be custom. Producer-structural labels must
  keep their meaning: `main` stays `main`, `unknown` stays `unknown`, and a `main`/`custom`/`unknown`
  agent_source (`main` source) is unchanged. `general-purpose`, `fork`, a plugin-shaped `<plugin>:<agent>`
  that is an allowlist member, an `a-<hash>` pseudonym, or an allowlisted safe custom name all pass
  through `sanitize` unchanged when the policy still permits them; a custom name whose allowlist entry was
  revoked must come back as its `a-<hash>` pseudonym.
- If re-sanitization changes the value, store the NEW value; the rest of the context is untouched. A
  malformed or missing agent block still drops the whole block, as today.

`sanitize` is pure and stdlib-only, so this adds no I/O and no new bound.

=== FIX B — the sidecar path is read for the wrong layout ===

The real on-disk layout is `<session-dir>/subagents/agent-<id>.jsonl` with a sibling
`<session-dir>/subagents/agent-<id>.meta.json` — the `subagents` directory sits directly under the session
file's directory (the session transcript is `<session-dir>.jsonl`), NOT under a directory named after the
session stem. Verify this in `producers/claude_code/cc_transcript.py` / `cc_hook.py` against how the
subagent transcript path is actually constructed, then make `cc_agent.read_sidecar_agent_type(path)` work
for the real layout:

- From the subagent transcript path, look for the sidecar at `Path(path).with_suffix(".meta.json")`; if
  that sibling does not exist, walk UP from the transcript's parent directory to the session root and try
  `<candidate>/subagents/agent-<id>.meta.json` at each level, so BOTH `.../<x>/subagents/agent-1.jsonl`
  and any deeper nesting are covered. Stop at the filesystem root or after a small fixed number of levels
  (<= 8) — this is a bounded local read inside the existing hook budget.
- Keep every existing guard: only read when the parent directory is named `subagents` and the file name
  starts with `agent-`; refuse a sidecar larger than 64 KiB; parse JSON and keep only the `agentType`
  string; never raise, never return the `description` or any other key.
- Do not read any other file.
