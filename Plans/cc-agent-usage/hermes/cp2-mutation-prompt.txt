CP2 MUTATION CHECKS — Claude Code agent identity + cc-input-size-v1

REPO: the Token Inspector backend checkout (branch `feat/cc-agent-usage`) at its CP2-integrated state.
Your job is NOT to change product code. It is to write ONE mutation runner, run it, and report which
mutations were caught and which survived. Leave the product code byte-for-byte unchanged when you finish
(the runner restores every mutation; verify this).

WHAT A MUTATION CHECK IS
For each control below: introduce a small deliberate defect in the source, run the named test, confirm it
goes RED (the assertion fails), then restore the exact original text. "Caught" = the test went red.
"Survived" = the test stayed green even though the control was broken — that is a missing test, and you
report it (do NOT fix the test).

RUNNER REQUIREMENTS (all mandatory)
- A single script (e.g. `/tmp/ccag_mut/mutate.py`), stdlib only, that has an `if __name__ == "__main__":`
  guard so importing it never applies a mutation.
- One mutation at a time. Apply by exact string replace; restore the ORIGINAL bytes in a `finally` block.
- Windows-safe subprocess: `subprocess.run(..., encoding="utf-8", errors="replace")`.
- After every mutation, re-read the file and assert the original string is present again before the next
  one (restoration verified). At the end, run `git status --porcelain` and confirm no product source file
  is modified (only the tests dir may be untouched too — the tree must be clean of your edits).
- Run each mutation with the repo's venv python: `.venv/bin/python -m pytest -q <test>::<name>` (fall back
  to `python3` if no venv). Use `-p no:cacheprovider` to avoid `.pyc` noise. Capture the exit code: non-zero
  = caught.
- Record for each mutation: id, target file, the one-line break description, the test id, caught/survived,
  and (if caught) the failing assertion line from the pytest output.
