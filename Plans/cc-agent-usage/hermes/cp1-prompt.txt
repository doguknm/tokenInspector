TASK: Analysis and implementation plan (READ-ONLY). Do not modify any file. Produce one markdown report.

CONTEXT
Token Inspector is a local, privacy-first FastAPI + SQLite service that stores LLM token telemetry
sent by producer hooks. Two producer codebases are in scope:
- backend repo (FastAPI app, ingest, storage, analytics, export): read-only worktree at
  /tmp/<RUN>/tokenInspector (commit matches the current main line).
- Hermes producer plugin (Python package that hooks the Hermes agent runtime): read-only worktree
  at /tmp/<RUN>/token_inspector.
(user home paths are omitted on purpose; "PEGA" and any other unrelated project is unreachable and out of scope).

The Claude Code producer (`producers/claude_code/cc_hook.py` in the backend repo) reads a Claude Code
JSONL transcript and POSTs token events. Today a Claude Code event carries:
- `role`: "primary" for the main thread, "subagent" for a subagent run;
- no agent identity at all;
- no complexity value.
The Hermes plugin computes a per-call complexity tier named `request-shape-v1` from numeric request
shape only (message length, message count, approx input tokens; see `token_inspector/complexity.py`),
so plugin events carry `complexity` and plugin-derived tasks carry `start_complexity`. Claude Code
events carry neither, so their tasks have no `start_complexity`.

Goal of the change (goal 1 of three): agent identity + per-call complexity for Claude Code, the DATA
layer only — producer, ingest validation, storage, task derivation, read API fields, export. The
dashboard "Agents" tab is a later goal and is NOT in scope here; this plan must specify the read-side
contract that the tab will consume.

- 18 640 assistant streaming groups ("calls"), 38 088 real-model assistant lines, 16 851 tool-result

  stop_hook_active, last_assistant_message, background_tasks, session_crons`.
  SubagentStop stdin adds: `agent_id, agent_type, agent_transcript_path`.
  SessionEnd stdin: `session_id, prompt_id, transcript_path, cwd, hook_event_name, reason`.
- Every subagent JSONL line carries `agentId` (= file suffix), `sessionId` (= parent session) and
  `isSidechain: true`; the first `promptId` in a subagent file equals the parent's Agent tool-result
  `promptId` (60/60 observed).
- Turn key = `promptId` of the most recent user line carrying one.
- `role` today is derived only from which file the hook is draining, not from any field.
- The existing call id is `cc-` + sha256(`message.id` U+001F `requestId`) and is idempotent per project,
  unique across projects (ADR-004).
